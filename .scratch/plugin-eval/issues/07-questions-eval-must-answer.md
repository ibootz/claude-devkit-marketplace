# 07: 评测要回答哪些问题

Type: grilling
Status: resolved
Blocked by: 无

## Question

对每类插件（skill / hook 注入 / hook 拦截 / output style），评测体系要回答哪些问题？候选：

- skill 该触发时是否触发、不该触发时是否误触发；
- 注入的纪律或风格是否被遵守，比不装插件好多少；
- 代价：常驻 token、时延、误拦次数；
- 多个插件同时生效时是否互相冲突；
- 升级版本后是否回归。

同时请用户说清 skill-creator 的评测「傻」在哪，作为输入。候选：只能评 skill；用例是编的单轮；判分靠字符串或自评偏宽；采样少看不出方差；只评有没有用不评代价；测不出插件互相干扰。

## Answer

2026-10-14 用户分两轮拍板。插件按**作用方式**分五类，一个插件可兼几类，每类各答各的问题（术语见 `CONTEXT.md`「插件评测」节）。

| 作用方式 | 必答 | 可选 | 不答 |
|---|---|---|---|
| skill | 该触发时触发；不该触发时不误触发；触发后照 skill 执行 | — | 触发早晚 |
| agent | 该派时派、不该派时不派；运行时照定义做事（工具限制、产出与回执格式）；回执交回后主会话能正确接续 | — | 模型档位（frontmatter 写死，机械可查） |
| 注入 · 纪律 | **逐条款**答遵守率及相对基线的差；compact 之后是否仍遵守 | — | 整份注入笼统打分 |
| 注入 · 文风 | 可机械判定的规则是否遵守；人读着累不累（用户终裁）；套文风后信息是否丢失、事实是否出错（与不装文风对照） | — | 与其它文风谁压过谁（并入干扰） |
| 拦截 | 真实会话命中次数与误拦次数；被拦后是否一次改对，不重复撞、不绕过 | — | 拦截逻辑正确性（单测负责）；危险操作是否变少（无对照组） |
| 副作用 | 真实会话失败次数、失败是否静默；额外花费（另起模型调用的 token 与时延） | 产物质量（只有调模型生成产物的才问，本仓目前只有自动标题） | 副作用正确性（单测负责） |

**跨类问题**：

- **代价**：常驻 token、hook 时延必答；误拦并入拦截类；评测本身的花费归 [08](08-cadence-and-budget.md)。
- **基线**：新插件比「不装」，改版比「上一版」。
- **干扰**：只答「被测插件与环境插件有没有冲突迹象」，不量化「同装后效果打几折」。

**skill-creator 评测「傻」在哪**（用户原话作输入）：判分靠字符串或模型自评、偏宽；测不出插件互相干扰；「没有 human 的介入」。追问后确认人工缺位在四个环节都成立：

1. **判分**：AI 评委或字符串判完即结论，无人裁定；
2. **用例**：AI 编的用例没人审就跑；
3. **结论**：报告出来直接入库或据此改插件，没人过目；
4. **选题**：会话复盘发现的问题哪些转成离线对照用例，没人挑。

四个环节都要留人工介入点。它们各以什么形态出现、每次要占用户多少时间，立为 [11](11-judging-and-human-checkpoints.md)。

**未选**：保留票面四类（skill / hook 注入 / hook 拦截 / output style）——装不下 agent 与副作用，且文风与纪律判分方式不同。

**残余不确定**：「待拍板不弹框」这类依赖 `AskUserQuestion` 的纪律条款在 headless 下缺被测工具，本票只定它是必答问题，怎么评仍在地图「Not yet specified」。

## Comments

### 2026-10-14 第一轮提问（待答）

已认领。盘点本仓组件：除 skill / hook 外还有 agent（devkit-omp、devkit-task-keeper）；output style 在本仓不是原生 output-styles，而是 hook 注入 `style/*.md`（wenyan、adhd、plain-talk、insight）；devkit-session-auto-title 这类 hook 只产生副作用、不经模型。据此第一轮问七件：skill-creator 傻在哪、插件按什么分类、skill 类问题、注入类问题粒度与 compact、拦截类问题、代价指标、基线与干扰深度。分类题定了之后再逐类排问题矩阵。

### 2026-10-14 第一轮答复

- Q1 skill-creator 傻在哪：**c 判分靠字符串或自评偏宽、f 测不出插件互相干扰**，用户补充「没有 human 的介入」。
- Q2 按**作用方式**分五类：skill、agent、注入（纪律 / 文风）、拦截、副作用。已写入 `CONTEXT.md`。
- Q3 skill 类必答：该触发时触发、不该触发时不误触发、触发后照 skill 执行。触发早晚不答。
- Q4 注入类**逐条款**回答；compact 之后是否仍遵守为必答。
- Q5 拦截类必答：真实会话命中与误拦次数、被拦后是否一次改对（不重复撞、不绕过）。「危险操作是否变少」不答（无对照组）。
- Q6 代价必答：常驻 token、hook 时延；误拦并入 Q5；评测本身花费交 08。
- Q7 基线：新插件比不装，改版比上一版。干扰只答「有没有冲突迹象」，不量化打折。

另：devkit-session-auto-title 的 hook 会起 `claude -p --model` 生成标题——副作用类也有质量与额外模型花费，第二轮问。

### 2026-10-14 第二轮答复

- Q8 agent 类：a 该派 / 不该派、b 照定义做事、d 回执后主会话接续必答；c 模型档位不答。
- Q9 副作用类：b 失败次数与是否静默、d 额外花费必答；a 正确性不答；c 产物质量可选。
- Q10 文风类：a 机械规则、b 易读性（用户终裁）、c 信息不丢必答；d 并入干扰。
- Q11 人工缺位：**a 判分、b 用例、c 结论、d 选题四处都是**。
