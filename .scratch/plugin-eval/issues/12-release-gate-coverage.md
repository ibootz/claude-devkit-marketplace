# 12: 发版闸门覆盖哪些版本

Type: grilling
Status: resolved
Blocked by: 08

## Question

[谁跑、何时跑、花多少](08-cadence-and-budget.md) 定了要做发版闸门：一个版本必须有已审的评测报告才能发版。同票又定了离线对照由用户手动触发、用户每月人工时间 ≤ 1 小时。近 30 天本仓有 23 次升版本，若每次都要已审报告，每月约 4 小时人工，三条无法同时成立。

要决定：

1. **闸门覆盖哪些版本**：所有升版；只覆盖改动碰到注入文本、skill description、agent 定义的升版（与 08 第 1 条的提示条件一致）；只覆盖 major / minor；还是由用户在升版时声明「本次需评测」。
2. **不在覆盖范围内的版本**怎么发：直接发，还是至少要规则判分子集通过。
3. **闸门落在哪一步**：本仓 `.githooks/pre-commit`（已在跑 `scripts/check-versions.js`）、推送前，还是发版说明里人工勾选；机制要能用于其它仓的插件，不能只靠本仓的 githooks。
4. **紧急修复**能否绕过闸门、绕过要留什么痕迹。

## Answer

> **2026-10-15 部分覆盖**：用户 2026-10-15 撤销美元花费上限（原话「由于我使用的是订阅 测评额度不适用 可以去掉 避免因为额度干扰了测评的质量」），随后拍板四项连带决定（原话「Q17 用最贵那一档 比如Fable模型 其他按照建议」），记录见 [08](08-cadence-and-budget.md) Comments。作废：第 2 条「子集大小受每月 $50 约束」及「对 Q2 花费的更正」一段的约束。现行：**规则判分子集取全部能用规则判分的用例**，不再限大小；只跑新版一臂、不调 AI 评委、不占用户审阅时间这三点不变。

2026-10-14 用户让 Jev 判 Q1–Q4 后拍板「按照jev的建议来」，含 AI 推荐与之不同的 Q2、Q3。Jev 原始输出见下方 Comments。

1. **闸门覆盖范围**：major 升版一律拦；另加用户在升版时**声明**「本次需评测」的版本。改动碰到注入文本、skill description、agent 定义时，AI 提示用户考虑声明（沿用 [谁跑、何时跑、花多少](08-cadence-and-budget.md) 第 1 条的提示条件）。
2. **闸门之外的版本**：发版前须通过一个**规则判分子集**——只用规则判分、不调 AI 评委、不占用户审阅时间，但要真跑模型。
3. **闸门落点**：机制提供一个通用的闸门检查命令（入参为插件目录），本仓**不接 git hook**，用户发版（推 main）前手动运行。
4. **紧急绕过**：提交信息写 `eval-skip: <理由>`，检查命令放行并记一笔；~~每周会话复盘的待审页~~**闸门检查命令每次运行时**列出所有跳过的版本，由用户决定是否补评（2026-10-14 随 08 第 2 条被 [09](09-build-vs-extend.md) 覆盖而改）。

**对 Q2 花费的更正**：提问时 AI 给 Jev 与用户的「每次 $2～10」是**完整有无对照**的估算，规则子集被高估了。按 [实测 claude plugin eval 能否评出 hook 注入的效果](05-probe-plugin-eval-on-hook-injection.md) 的单 run 实测 $0.05～0.31：只跑新版一臂、每例 1 次、2～3 个用例，每次约 $0.15～0.9；每月约 37 个闸门外版本，合计约 $6～33，能落在每月 $50 内。**约束交给 09：子集大小必须让「每月升版数 × 子集单价」不超过每月 $50 减去对照与复盘的花费。**

**用户知情后仍采纳的风险**：Q3 手动运行检查，与 08「要做发版闸门」之间靠人记。本仓 `.githooks/pre-commit` 注释记录过同类先例：「靠文档提醒的实际执行率是零」。

**未选**：所有升版都拦、只拦碰内容的升版、只拦 major；闸门外直接发；pre-commit、pre-push；不提供正式绕过。

**重开条件**：~~每周会话复盘~~闸门检查命令（2026-10-14 改，理由同第 4 条）若发现闸门内的版本（major 或已声明）推到 main 时既无已审报告、也无 `eval-skip:` 记录，重议第 3 条，改接 pre-push。
