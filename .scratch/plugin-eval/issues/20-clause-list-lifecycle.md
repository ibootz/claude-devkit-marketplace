# 20: 条款清单的生命周期

Type: grilling
Status: resolved
Blocked by: 无

## Question

[离线对照的用例从哪来、怎么构造](17-case-sourcing.md) 定了冷启动时 AI 按**条款清单**起草用例——注入类插件逐条款出结论（[评测要回答哪些问题](07-questions-eval-must-answer.md)），用例、金标样本都挂在条款 id 上。清单本身随被测插件改版会变，要决定：

1. 被测插件的注入文本改版时，谁、在什么时机重抽条款清单（跑离线对照时自动、闸门检查命令提示、还是用户手动）。
2. 条款拆分、合并、删除时，旧 id 和挂在它上面的用例、金标样本怎么处置（迁移、作废、保留只读）。
3. 闸门检查命令要不要在「本版改了注入文本」时提示重抽清单；与 [缺口里哪些自建、以什么形态](09-build-vs-extend.md) 定的「升版碰到注入文本时提示跑对照」是同一条提示还是两条。

来源：17 关票时写进地图 Not yet specified，2026-10-15 毕业为本票。

## Answer

2026-10-15 用户一轮拍板，原话「全部按推荐」。Jev 不可用（`fetch failed`），五题只有 AI 推荐。术语见 `CONTEXT.md`「插件评测」节（条款清单、注入文本指纹、退役条款）。

**1. 过期判据：注入文本指纹。**
- 在真实 HOME、空临时 cwd 下执行被测插件全部注入 hook（SessionStart / UserPromptSubmit 等会输出注入文字的事件），取输出文本算指纹。
- 条款清单记下抽取时的注入文本指纹；当前指纹与之不同即「清单过期」。只认文字真变，重构脚本、改无关 hook 不触发。
- 不能复用 [跑评测前检查哪些前置条件](15-preflight-checks.md) 的 hook 冒烟那次执行：冒烟用临时空 HOME，本机 asdf shim 在空 HOME 下全部 `rc=126`，取不到文字。
- 依赖项目目录或条件成立才输出的注入（条件注入），空目录下取不到，记为残余不确定。

**2. 重抽时机：跑离线对照的第一步，自动、增量。**
- 跑对照时先比注入文本指纹；过期则 AI 只读旧清单加新旧注入文本的差异，输出清单变更（新增、改写、退役），进本次待审页，整份变更算 1 项。
- 用户确认前对照照跑：新条款在报告里列「无用例」，报告标注「条款清单待确认」。不中止——待审报告本就不能作改插件或发版的依据（[判分分工与人工介入点](11-judging-and-human-checkpoints.md) 第 5 条），未审条款列「无用例」不算失败（17 第 8 条）。
- 指纹未变则不重抽，不产生待审项。

**3. 旧 id 与用例、金标的处置：id 绑判定标准，退役不删。**
- **id 绑定判定标准，不绑定措辞**：判定标准不变，改措辞也保留 id；判定标准变了即换新 id。拆分、合并都按「旧 id 退役 + 新 id」处理。
- id 永不复用。退役条款留在清单里，标「退役」并写替代它的新 id（删除的条款不写替代）。
- 挂在退役 id 上的用例退回 `drafts/`，附 AI 的改挂建议；用户在待审页勾选后回到 `<plugin>/evals/`，复用既有的草稿勾选机制，不新增状态。
- 条款删除时，其用例在待审页经用户确认后删除，git 历史留底。
- 金标样本不删，挂在退役 id 上的停止参与评委校准；替代条款意图一致的，由 AI 建议迁移、用户确认后生效。同一 id 下判定标准不变，金标因此始终有效。
- `run.json` 记本次所用条款清单的指纹，旧运行的逐条款结论仍能对上当时的清单。

**4. 闸门提示：合成一条。** 闸门检查命令发现注入文本指纹相对上次对照变了，输出一条「建议跑对照（会先更新条款清单）」。重抽是跑对照的第一步，不另设提示、不另设命令。这细化了 [缺口里哪些自建、以什么形态](09-build-vs-extend.md) 缺口表「升版碰到注入文本」一行：注入文本部分的触发条件由「改动碰到注入文本」落实为注入文本指纹变化；skill description、agent 定义两部分不变。

**5. 本票落盘**：同 17，用 `Bash` 对本票、`map.md`、`CONTEXT.md` 及受影响票做定点写回主仓，写前重读磁盘。

**未选**：`git diff` 命中 `hooks/**` 即算改了；每次升版一律重抽；闸门提示后用户手动跑重抽命令；完全手动；过期即中止对照；清单一变整体作废旧 id、用例与金标；AI 自动改挂不经用户确认；旧用例照跑归「退役条款」栏；闸门两条独立提示；只写 worktree 副本；把地图入库提交。

**残余不确定**：
- 条件注入（依赖项目目录、会话状态才输出的文字）在空目录下取不到，这部分改动不触发重抽。2026-10-15 实测本仓 27 条注入 command 在空 cwd 下两次输出逐字一致，其中 devkit-worktree-flow、devkit-omp 等部分 command 在空目录下无输出。
- 注入文本里若含时间、随机数等每次都变的内容，指纹会恒为「过期」；本仓未见，属实施时要处理的归一化细节。
- AI 判「判定标准是否变了」可能判错，靠待审页那 1 项兜底。

**重开条件**：
- 会话复盘发现某条款的注入文字已改、清单却从未提示过期（条件注入漏判），重议第 1 条的取文本方式。
- 条款清单变更连续两次在待审页被用户整份打回，重议第 2 条「增量重抽」。
