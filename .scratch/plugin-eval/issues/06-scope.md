# 06: 评测范围

Type: grilling
Status: resolved
Blocked by: 无

## Question

两件范围上的事：

1. **「已用」指什么**：用户原话「已用的插件评估体系」。是从真实会话记录（`~/.claude/projects/**.jsonl`）里事后统计插件的实际表现，还是事先造用例跑离线对照，还是两种都要？
2. **覆盖哪些插件**：只评本仓 `devkit-*`；再加 radnove 内网市场的插件；还是评本机实际启用的整套组合，不分市场。

建议：第 1 问两种都要，以真实会话分析为主、离线对照做复核；第 2 问只评 `devkit-*`，给「本机实际启用组合」预留接口——radnove 与真实会话里都有内网内容，进公开仓有泄漏风险。

## Answer

2026-10-14 用户分两轮拍板，五个选择如下。

1. **两条路都做，不分主次**（第 1 问选 c）。
   **会话复盘**负责发现问题，并给**离线对照**提供用例素材；离线对照负责量化有无被测插件的差距与版本回归。先建哪条交给 [08](08-cadence-and-budget.md) 与 [09](09-build-vs-extend.md)。
2. **只评被测插件，其它插件都是环境插件**（第 2 问选 a）。
   用户补充：要的是一套**通用机制**，能评任何自己写的插件，一次评一个。`devkit-*` 是第一批使用者，不是边界。
3. **机制放本仓；每个被测插件的用例与结果放在该插件自己所在的仓**（Q3 选 a）。
   机制只接收一个插件目录作参数，不写死本仓路径。评 radnove 插件时，用例与结果进 radnove 内网仓，不进公开仓。
4. **会话复盘的原始 jsonl 不入库，也不另存**（Q4 选 a）。
   入库的只有抽取结果：会话 id、时间、命中的规则名或 skill 名、次数，不含对话原文。本机 `cleanupPeriodDays` 为 90，所以 90 天后无法回看原文，用户接受这个代价。
5. **干扰由会话复盘发现，离线对照默认用纯净环境**（Q5 选 b）。
   离线对照留一个口子：可以手动加一两个指定的环境插件，复现已经发现的冲突。05 已证实沙箱可以同载多个插件。

**未选**：
- 只做离线对照或只做会话复盘；
- 被测插件集中放本仓，或放进新建的私有仓；
- 违规处原文片段脱敏后入库、原始 jsonl 本地归档；
- 离线对照默认带上本机整套插件。

**残余不确定**：会话复盘能从 jsonl 里取到哪些信号，以及能否把现象归到具体插件，还没实测，已立为 [10](10-session-jsonl-signals.md)。

**重开条件**：
- 10 查出 jsonl 无法把现象归到具体插件，第 1、5 条要重议；
- 出现需要同时评多个插件的需求，第 2 条要重议。
