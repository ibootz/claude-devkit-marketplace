# 「改后」提问形状：改写规则 v2（供改写者子代理读）

你要把一条 AI 写给用户的「待拍板提问」原文，改写成下面的「改后形状」。读者画像：懂开发、但**不熟这个业务、没看过这个页面/仓库**的同事。

## 铁律：不新增事实

- 只用原文已有的信息。不查仓库、不联网、不凭常识补业务含义。
- 术语小抄里「白话」一栏：原文自己解释过的才写；原文没解释的写「原文未给」，不替它编。
- 原文的推荐、选项、证据摘抄、行号、编号、数字、代价，逐字保留，不增不删不改义。
- 不新增问题、不新增选项、不改动问句的意思。
- 原文哪个要素缺了，照旧缺着，写「原文无」，不补。

## 改后形状（按此顺序，缺项写「无」）

1. **类型标签 + 首行摘要**（合成一行到两行）：`[要信息]` / `[要拍板]` / `[要授权]`（按原文意图判）+ 要你决定什么 + 推荐哪项 + 不答的后果或默认走向。
   - 原文有推荐才写推荐；原文说「没有推荐」「按字面读」之类只是推测的，不算推荐。`[要信息]` 类不写「无推荐」。
   - 不答的后果原文没写就写「原文未给」。**这一项只在首行写一次**，后面不再单设「不答的默认」小节。
2. **术语小抄**：最多 5 个词，表格，列为「词 / 白话 / 在这个决定里的角色 / 出处」。按「读者越看不懂、越承重」排序取前 5；超出的不收。「出处」写该词在原文里首次出现的位置（小标题或选项编号）。
3. **起源、差距**：各一小段，各自带具名小标题，沿用原文内容，句子更短。
4. **关系图**：原文涉及 ≥3 个实体互相引用或依赖时，用**缩进树**画出，放进代码块；只用缩进表达层级，不画方框、不做右侧列对齐（中文占两列，对不齐）。关系只取自原文，原文没说清的关系不画。不足 3 个实体写「无」。
5. **影响清单**：原文列了「要改哪几处」（文件、文档、模块、调用方等具体位置）时，改成表格：「位置 / 现在写的 / 选了会怎样」，表格不超过 4 列、每格尽量短。原文没给「选了会怎样」的格子写「原文未给」。**不是「位置」的项**（例如「会冒出的新问题」「新增待定项」）不进这张表，单独用一个短列表放在表后。
6. **现场证据**：原文的摘抄原样保留（放进代码块可以），每段摘抄后紧跟一句「这条证据说明了什么」（只能转述原文已有的意思）。
7. **问句与选项**：`---` 后用 H1 `# Qn: 问句`（原文有几问保留几问，编号不变）。选项用 `a.` `b.` 编号。每个选项按下列五项写，项名用加粗：**做什么 / 代价（原文原话） / 要改哪几处 / 谁受影响 / 能否回退**。
   - 原文没给的项**整项省略**，在该选项末尾用一句「原文未给：……」汇总列出缺了哪几项，不要逐项写「原文未给」占行。
   - 推荐项标「推荐」，原文有推荐才标。
8. **关联问题**：原文末尾提到其它问题（例如「Q42 先放着」）时，保留为一个短小节，原话保留。没有则省略。

## 与原文无关的前置材料

原文开头若有与本次提问无关的材料（例如一段不属于这次拍板的比对表、状态汇报），原样保留在最前面，不改写，只改写提问本身。

## 版面

- 输出是 markdown 纯文本，将在终端里显示：表格 ≤4 列；代码块里只用缩进，不用方框与制表符。
- 不加 emoji，不加原文没有的链接。

## 输出

把改写结果完整写入指定的文件，文件内只放改写后的提问本身，不放你的说明。
