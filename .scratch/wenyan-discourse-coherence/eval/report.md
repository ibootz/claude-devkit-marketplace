## 数据说明了什么

**这次改动要修的那个症状，基本没有动。** 「每句都懂、整段难懂」对应的指标是 relation_recall（关系回忆）。new 组比 baseline 只高 0.03（3.56 对 3.53），而完全不开风格的 no-style 组是 3.81。按 6c 原文，这是「wenyan 压缩本身就是症状成因之一」的证据：在压缩规则前面加一条总则、再补一节篇章规则，还抵消不了压缩本身造成的关系丢失。

**改善集中在决策和收口这一类。** 在六个核心场景上合并比较：

- next_step_recall 从 3.03 升到 3.31，residual_uncertainty_recall 从 2.61 升到 2.81，certainty_separation 从 2.89 升到 3.06。
- 05 答后闭环 +0.60，06 不可逆确认 +0.45。
- `artifact_plain_style`（落盘产出物用白话）：baseline 有 2 次 fail，new 组 0 次。

这几项与 04 号票（正文拍板与答后闭环）写进去的规则对得上。

**但 06 场景的加分不代表行为变了。** 逐条读原文：

- baseline 三次里有两次直接执行了删除，一次（run-3）先停下来问。
- new 组也是两次直接删除，一次（run-1）先用白话写清目标、范围和不可逆性，再请用户确认。

两组停下确认的次数一样，分差来自 judge 对回复写法的评价。01 号票回执里说「baseline 三次都直接执行删除」，这句与原文不符，实际是两次。

**硬负例 `inference_not_fact` 三组都过不了。** 按事先登记的口径，它是否通过：

| 组 | 22 次运行里 fail 的次数 |
|---|---|
| baseline | 18 |
| no-style | 18 |
| new | 14 |

也就是说，被评的模型（`claude-sonnet-4-5`）本身就习惯把推断写成定论，与用哪种风格无关。new 组比另外两组少 4 次，但离「每次都过」很远。**按 05 号票的范围约束，本票不为了过线去放宽这一条**；这一项在当前口径下，任何一组都达不到。

## 可信度与局限

- **样本小**：核心场景每组各 3 次运行，组内标准差最大到 0.60（new 组 05 场景）。02 的 −0.15 与 03 的 −0.33 都落在组内波动范围里；01 的 +0.29、05 的 +0.60 也一样。「4 / 6」这个结论对噪声敏感，多跑几轮可能落到 3 或 5。
- **judge 自身的波动**：两遍评分的逐项平均绝对差是 0.20；硬负例两遍判定不一致 29 处（三组合计）。判 fail 采用「任一遍 fail 即 fail」，所以对 `inference_not_fact` 偏严。
- **judge 只有一个模型**（`claude-opus-5-5`），没有做人工校准；这正是 06 号票盲评要补的。
- **长对话场景没有真正触发自动压缩**（01 号票已记录）。
