# 中文消歧（zh-disambiguate）

Status: ready-for-agent

## 背景

用户提供了一份「ASD-STE100 第 9 版中文适配」的讨论稿。结论是：中文适配的重点不是把英文 STE 的词数、词性、时态、冠词规则翻译过来，而是消除中文歧义——让每个关键句的执行者、对象、作用范围、动作状态和确定程度都能从字面读出。

本 spec 把这份结论落到本仓插件上。决策来自 2026-10-02 至 2026-10-03 的一次 grilling 会话（Q1–Q14）。

## 现状缺口（改前）

| 要求 | 现有覆盖 | 缺口 |
|---|---|---|
| 术语一致 | plain-talk / wenyan / adhd 的「不自造词」 | 只管名字来源，没管「同一概念不换词、不同概念不合并」 |
| 指代明确 | plain-talk 第 6 条「指名道姓」 | 只在一个风格插件里 |
| 执行者明确 | 无；wenyan 第 1 条「省主语」与之冲突 | 空白 |
| 动作状态 | wenyan 只把「已、未」列为承转虚词 | 没要求写明状态 |
| 量词 / 否定 / 条件范围 | 无 | 空白 |
| 保留不确定性 | working-discipline 3.4 求真 | 已覆盖，不重复 |
| 原意检查 | 无 | 空白 |

## 决策

| # | 问题 | 选定 |
|---|---|---|
| Q1 | 约束哪类文字 | 对话回复 + 落盘文档（写给 agent 的文字仍归 `writing-for-agents`） |
| Q2 | 落地形式 | 常驻规则 + 按需 skill |
| Q3 | 概念表放哪 | 复用项目自己的 `CONTEXT.md` |
| Q4 | wenyan 省主语冲突 | 改 wenyan 第 1 条：可能执行者 ≥2 时不省主语 |
| Q5 | 常驻放哪几条 | 执行者、作用范围、动作状态、概念不合并；「一句一条指令」只进 skill |
| Q6 | 常驻放哪 | working-discipline 新增 3.11，只写一句总则，细则在 skill 的 reference |
| Q7 | 形式层要不要脚本 | 要；只预警不判定；句长阈值 60 字（未实测，待校准） |
| Q8 | skill 名 | `zh-disambiguate` |
| Q9 | 子代理层是否注入 3.11 | 主会话与子代理两层都注入 |
| Q10 | 哪些落盘模板引用 3.11 | spec.md、tasks.md、issue.md、decisions |
| Q11 | skill 何时触发 | 用户明确要求；spec-analyze 第 5 阶段落盘前自动调用 |
| Q12 | skill 放哪 | working-discipline 的 `skills/` |
| Q13 | 审计还是改写 | 默认只审计；用户说「改」才改写，改写须过原意检查，缺失事实只标记不补造 |
| Q14 | 确认执行 | 已确认 |

Q6 原推荐「四条全进常驻」。子代理实测 working-discipline 注入离 5000 字符自律线只剩约 400–480 字符，放不下，因此改为「一句总则 + 细则按需读」。落地后实测：SessionStart 4782、SubagentStart 4714（可派发类型）、3877（Explore / Plan）。

## 不做的

- 不写 ADR：改动都可回退，不满足 ADR 三条件中的「难以回退」。
- impl.md 与 key-module-analysis 的 11 个模板暂不引用 3.11，等 3.11 运行一段时间看效果再定。

## 残余不确定与重开条件

- 60 字句长阈值没有实测依据。重开条件：用本仓现有 md 跑一遍扫描脚本，误报率明显过高就调整。
- 120–200 字的总则能否单独管住模型，待观察。重开条件：落地后仍频繁出现执行者缺失或范围不清的输出，再考虑把细则挪进常驻注入（需先腾出字符预算）。
