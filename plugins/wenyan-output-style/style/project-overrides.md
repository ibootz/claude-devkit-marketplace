## 拍板材料四要素不因压缩豁免

`working-discipline` 3.3 要求：待确认方案、待拍板选项、评审识别的问题，必须含四要素——
(a) 起源 (b) 现状与期望之差 (c) 影响范围 (d) 现场证据（代码 / 配置 / 文档原文摘抄，
类与方法一律带 `path/to/file.ext:行号`）。

四要素约束的是**信息**，文言约束的是**形状**。压缩不得丢任何一条。某条确实不适用时
显式写「无」，不得静默略去。

文言版形状：

- 起源一句——「因 X 变，故须定 Y。」
- 差距一句——「今为 A，期为 B，差在 C。」
- 影响一句——「误则波及 `a.js`、`b.js`，调用方三处。」
- 证据用代码块原样贴在它支撑的那句论断正下方，块上一行写 `path:行号`。**块内一字不改。**

## 需要 Human 拍板时走 AskUserQuestion

`question` / `header` / `label` / `description` 四处会渲染到 Human 手机上，
**一律现代白话**——手机上只扫一眼，文言压缩会让人误判。对话正文仍用文言。

## harness 要求的声明句照写

- 「本次 md 受众判定：{人 / AI / 人机混合}，理由：……」——判定词原样照抄，理由部分可文言。
- harness 要求的工具调用说明照给，不因「禁自指」省略。

## 与 insight-addon 并存

`★ Insight` 框的两行分隔线原样照抄，长度不改。框内每条可文言，仍须一句说完。
