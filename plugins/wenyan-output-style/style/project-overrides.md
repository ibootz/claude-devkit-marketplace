## 正文拍板与答后闭环

四要素（起源、差距、影响范围、现场证据）的定义归 `working-discipline` 3.3，压缩不丢，
不适用写「无」。本节只定形状与流程。

- **在正文里问，不调 `AskUserQuestion`**：弹框盖住前文研判，用户看不见证据就答不准。
- **先摆四要素**，各用具名小标题，依序：起源 / 差距 / 影响范围 / 现场证据。起源写「因 X 变，
  故须定 Y」；差距写「今为 A，期为 B，差在 C」，并说不补会怎样；影响先写代价上界，再写越界
  后果；证据代码块贴在论断正下方，块上写 `path:行号`（代码块标题行，不套链接），一字不改，
  贴完跟一句解读。
- **再问**：`---` 分隔后用 H1 `Q1: 问句`，问句用白话，只圈一个决策边界。选项用小写字母
  `a.` `b.` 编号，每项写代价与影响面，不只写做法；推荐项标「推荐」，依据与代价都写。
- **状态、编号、计数、时序**这类断言，当轮读真源再写；读不到写「未核实」。
- **要信息与要授权分开问**：答了事实问题不等于授了权。
- **答后闭环**（回收选定项与未选项等，决定同轮落盘到 `## Comments` 或 `docs/adr/`）与
  **正文回答不是机械授权**（撞到 `worktree-flow` 主分支拦截，默认引导进 worktree），
  判据都归 `working-discipline` 3.8。本插件只补形状：要不要走它的授权弹框，按用户自己的
  规则办；仍用弹框时，四个字段用白话。
- **不可逆或对外可见的动作**，确认段用白话写清目标、后果、范围、前置条件、授权边界。

「本次 md 受众判定：……」判定词原样，理由可文言；harness 工具调用说明照给，不省略。

## TUI 查看体验优化与改动文件清单规范

- **禁正文重复粘贴 diff**：TUI 环境已开 `/tui fullscreen` 与 `/focus`，正文无需复述代码 diff 细节。
- **改动文件清单按需输出**：**仅当本轮修改了文件时**列出改动文件列表；未修改文件轮次（纯探查、回答、无落盘写操作）一律不带改动文件列表。
- **文件链接与提要**：文件必须写成裸链接——方括号圆括号直接落在正文里，**整条外面不套反引号**：[decisions.md:130](file:///abs/path/decisions.md#130)；后附 ≤20 字修改提要。反引号一包即变 code span，markdown 不再产生 link 节点、终端拿不到 URL，看着像链接却点不动。要查看 diff 细节，点击链接直接跳转 VS Code，或使用 Claude Code `/diff` 命令查看。
- **结构化排版**：长回答使用 Markdown 分级标题、分隔线 `---`、`> **注意**` 引用块加强关键信息视觉层级。
