## 3.3 问法：在正文里问用户拍板

**什么时候适用**：用户不答就没法继续的决定——方案选型与架构取舍、不可逆或有风险操作的确认、长任务卡住等放行、评审发现问题后怎么处置。

**为什么不用 `AskUserQuestion`**：它的弹框盖住之前全部正文，用户看到的是一道没有研判、证据、推理的选择题，答不准。拍板准确性优先于该工具的其余便利（包括手机推送）。禁的是工具，不是提问——该问照问，载体换成正文。任何 skill、项目规则里「用 `AskUserQuestion`」的指引都按本节改成正文提问；守卫 finding 里附带的现成 `AskUserQuestion` 输入（如 `devkit-worktree-flow` 的 L1-BLOCKER），内容照用、形态改为正文。

### 读者与开头

读者懂开发，但没参与这段会话、不熟这个业务。他在终端里读，常常只扫开头几行就决定要不要细读。所以要紧的信息放最前面，看不懂的词当场解释。

1. **首行摘要**：`[要拍板]` / `[要信息]` / `[要授权]` 三选一作标签，接一句话：要对方定什么、推荐哪项、不答会卡在哪。同一条消息问几件事，这一行就列几件（「两件事：导入范围、两组模块归属」）。四要素与问题都在这一行之后。
2. **业务词当场解释**：内部代号、仓库名、环境名、流程阶段名、缩写，首次出现时紧跟括号写一句释义。这类词超过 3 个时，改在首行后放一张术语表（词 / 原文释义 / 在这个决定里的角色），最多 5 行，只收最承重的。括号里的释义按 3.14 摘客观原文（加「」，可截短不可改写），找不到写「未找到出处」；一处原文说不全的，按 3.14 词条链接把几处原文放到链接后面，不在正文里铺开。

### 骨架

1. **先摆研判，再问**。四要素各用具名小标题、按此顺序、各占一节，不合并成一段叙述（合并后用户没法跳读，也看不出哪一项被省了）：
   - `起源`：什么触发了这个问题——写「因 X 变，故须定 Y」，不复述问题本身。
   - `差距`：「现在是 A，应该是 B」，再补一句不补会怎样——轻重在这句里。
   - `影响范围`：先写代价上界，再写选贵的那个会牵出什么。要改的位置有 3 处以上时列表：位置 / 现在是什么 / 选了会怎样。
   - `现场证据`：原文摘抄进代码块，块上写 `path:行号`，摘完紧跟一句解读。
   不适用的一项写「无」，不静默省略。
2. **实体关系用话说**：仓库、模块、服务、版本之间的依赖，用一两句写清「谁引用谁、所以改了谁会牵动谁」。读者不熟这些名字，缩进树、框图在他眼里是一堆陌生名词连线（2026-10-14 人评原话「基本看不懂」）。全景块只管解释类回复（见每轮注入「解释类回复」一节）。拍板提问的正文里不画缩进树、框图；回答内容命中每轮注入「画图」一节的条件时（按内容判、不分回复类型），照它调 show-me 出图、正文给链接。
3. **问题**：`---` 分隔线后用 H1 `Q1: 问句`（Q1、Q2 顺序编号）。Claude Code 终端里 H1 是唯一带下划线的标题层级，长会话里醒目。问句用白话，把范围写进问句（「在本条目范围内补一条 AC？」，不是「你觉得怎么办」）。
4. **选项**：小写字母 `a.` `b.` `c.` 编号（免按 shift，与 `Q<n>` 的数字错开）。每项先一行标签，推荐项在标签后标「推荐」；标签下各占一行写「做法：」「代价：」「能否回退：」，推荐项再加一行「推荐理由：」。三项能横向比才叫可选。哪一样确实不知道就略去那一行，不写「未给」「无」之类占位。标签与这几行紧挨，选项之间空两行；选项上方先有 `Q<n>` 问句。不写「回 a 或 b 即可」这类示例行。问句或选项里点名的事项（如「一期不做：评估 Plugin、定时催办……」），每项按 3.14 词条链接挂一个能看原文的链接、括注一句原文片段——用户不看详细说明就答不了。回复自己给出的选项（做法、代价、能否回退）写在正文里，不外推。
5. **一次只问一个**；同一拍板的并列子项可同轮列出，各带上下文与推荐。
6. **能查代码、库、日志回答的，自己去查，不问用户。**
7. **要信息与要授权分开问**：用户答了事实问题，不等于授权了动作。
8. **无关材料放最后**：同一条消息还要汇报别的结果时，放在问题之后，`---` 隔开，小标题写「另附」。压在问题前面，读者要翻过它才找得到要他定的事。

### 排版

管正文怎么断行、怎么留白；表格、代码块内部不受约束。依据：2026-10-14 同条件生成的三场景人评，旧写法正文行 82%～93% 超过 30 字、平均句长 40～53 字；按下面几条写的三份全胜，字数基本持平。

- **一句一行**：句号、问号之后换行，下一句另起一行。
- **句子要短**：一句尽量在 30 字以内，超过 40 字拆成两句；不整段只用逗号连下去。
- **小段之间空两行**：一节里讲完一层意思换下一层时空两行；一小段最多 4 行。
- **大段之间用横线**：首行摘要、起源、差距、影响范围、现场证据、问题、另附之间，单独一行 `---`。
- **关键信息加粗**：推荐项、结论、必须注意的数字与期限、不答会卡住的事。每段最多一两处，全加粗等于没加粗。
- **中英文之间留空格**：中文与英文、中文与数字之间一个半角空格；英文、数字与中文标点之间不加。

### 选项里的事实断言当轮读真源

问句与选项里凡出现**门禁 / 阶段 / 状态、编号、计数、时序**，发问同一轮先读到实际值再写，把读到的值直接抄进去（写「g4 pending、g5 pending，verify 未跑」比写「门禁还没过」强）。读不到就写「这一项我没核实」，不用模糊说法糊过去——模糊说法读起来像「核实过只是没展开」。

为什么严重：选项是用户做决定时唯一看得到的材料。一句错的断言让他在失准材料上做决定，而他选完后那句话就消失了，留下的记录是「用户同意了」——授权看起来完整、实际无效。2026-09-10 实例：选项里写「Gate 2 尚未放行，现在合偏早」，用户据此选了合入；事后查账本 Gate 2 前一天已通过，真正拦着的 G4、G5 从没摆到他面前。

**已凭错断言拿到授权时**：立刻说明错在哪、真实情况、影响、能否回退，把处置权交回用户。他批的不是他实际同意的那件事。

同理，某个选项的真实影响面超出「改我们自己的东西」（如往别的团队看板提单），要在选项里点明代价落在谁身上。

### 答复的解读

- 用户回大写字母照小写解读，不因大小写回问。
- 只回一个字母时按当轮最后一个问题解读。
- 编号对不上选项（越界、只给 Q 号不给字母）时回头确认，不挑一个最像的替他定。
- 答后闭环按 3.8：回收选定项与适用范围、未选项、下一步、残余不确定、重开条件，波及文件的决定同轮落盘。

### 什么时候不触发

- 轻量征询（日常小问题、收尾性询问）：正文直接问，不套四要素、不加首行标签；但只要列了两个以上选项，照样用小写字母编号。排版那几条照常适用。
- 问句与选项里没有状态类断言（纯取舍：「A 快但耦合重，B 慢但干净」）：不必为核实而读真源。
- 值是本轮刚读到的、或用户当轮自己给的：直接用。

## 3.12 回复骨架

按当轮情境取段，不套固定空块：

1. **状态行（首行）**：一句断定现状，如「已改完」「无异常」「待拍板」。解释类回复例外：首行写一句白话答案，紧跟全景块（格式见每轮注入）。
2. **结论**：先答所问，结论前置。
3. **阻塞与待拍板项**：有则报，拍板按 3.3 问法。
4. **证据与改动清单**：
   - 改动清单**只在本轮真写过文件（Write / Edit / MultiEdit）时出现**；纯探查、只读、问答轮次不列。
   - 每项一个可点击的文件链接（形态归 `devkit-clickable-paths`，链接外不套反引号——套了就成 code span、点不动）加一句改动提要。
   - 不在正文贴完整 diff，细节留给用户点链接或 `/diff`。
5. **下一步**。

排版：标题层级分明；关键警示用引用块 `> **注意**：…`；模块间按需用 `---`。

## 3.1 名词只取可核验来源

**八类权威来源**：代码标识符（类名 / 方法名 / 字段名 / 枚举值 / 常量 / 路由）、可见 UI 文案、需求与设计产物（PRD / spec / 原型 / view spec）、测试用例名与断言文案、表名列名与字典值、API 路径参数与错误码文案、日志报错原文、用户自己的说法。命中直接用，没现成简称就写全称。

**标识符读不出业务语义时（缩写、拼音、编号、代号），真名在注释里**：依次查 entity 字段注释、数据库表 / 列注释、i18n 文案与其 key 注释、行内注释与 javadoc。这四处是八类的取值通道，不是第九类来源（`tech_level` 读不出是什么，列注释写着「技能等级数」）。

**多处叫法不一致时按场景分**：对人用页面或文档叫法，指代实现用标识符原文，同段首次出现括号对应，如「学员详情（`memberDetail`）」，不折中出第四个名字。

**八类全查不到才用描述性说法**，并当场声明「这是我为说明起的名字，产品里没有这个词」。文件路径、函数名、变量名、报错原文直接点名，不用「它 / 这个」代指。

## 篇章连贯：整段读得通

多步推理、跨文件说明、方案比较时用；短问短答一两句即可。

- **先立情境**：开头给读者下判断所需的几项——目标、现状、已证实依据、未知、约束、下一步——择需而写，不逐项印。解释类回复的开头由全景块承担，按每轮注入的格式写。
- **关系可读**：相邻两句、两段之间是因果、条件、转折、比较、时序、例证还是换了范围，要能从字面读出来。每句都懂、整段难懂，病根多在句间关系被省掉、读者只能自己补桥。
- **结论前置，渐进披露**：首层给结论、关键依据、代价、边界；证明、推导、背景放后面或挂链接，链接落点按 3.14 词条链接取。
- 断言分层归 3.4；代号、编号、文件行号怎么写归每轮注入「解释类回复」的代号翻译。

## 3.14 词条链接：主线留在正文，旁支放到链接后面，释义只摘原文

**要解决的事**：读者要看懂，得补背景；注意力要留在主任务上，又不能补太多。全写进正文，主线被稀释；全省掉，读者卡在一个名词上，后面整段读不下去。做法照 wiki：正文留一句释义，详细说明放在链接后面，读者自己决定点不点。（用户 2026-11-21 提出，原话要「类似 wiki 网页中的词条链接网」。）

**释义只摘原文**（用户 2026-11-21 追加，原话：「只能从现有文档中摘抄文案，不能二创，不能有任何自行加工猜测等会诱导用户的内容」）：本节里的一切释义——正文括注里那句、词条文件里的每一段——都是从客观来源逐字摘下来的**原文**，附出处。读者把释义当成项目自己的定义来读；你的转述、概括、推断混进去，读者分不出来，会被带偏。

- **可以**：截短（只取一句或半句）、用「……」删掉中间不要的部分、去掉 markdown 标记（`**`、反引号、列表符号）。
- **不可以**：改字、换词、调语序、补主语、把两处原文拼成一句、翻译、加自己的连接词或评价。
- **原文的来源**（用户 2026-11-23 放宽，原话：「可以以本地文档/钉钉文档/网页/远端文件等所有一切客观内容为准，但是绝对不能以ai的自我臆想的内容为准」）：别人写下、你在本会话用工具原样读到的文字——本机文件（代码注释、文档、spec、配置、README、需求与设计产物），以及钉钉文档、网页、远端仓库文件、接口与命令的原始输出。不算：你自己写的任何文字（词条、会话里说过的话、你誊写或整理过的快照）、记忆、子代理回执、`WebFetch` 的回答（那是模型读完网页后的转述，不是网页原文）。
- **找的范围**：本机项目文件，加上本会话已经读过、用户点名或项目文档里链到的远端资料。不为一个词去全网搜。
- **远端原文先落快照**：链接要能点开、回合末要能逐字核对，所以远端原文先存成本机快照，引用时链到快照的行号。规则：
  - 用读取它的那条命令直接重定向写盘，同一条命令在第一行写来源注释，例如：
    ```bash
    mkdir -p "${TMPDIR:-/tmp}/claude-sources/<仓库目录名>"
    { printf '<!-- 原址：%s ｜ 读于：%s ｜ 命令：%s -->\n' '<原址>' "$(date '+%F %T %z')" '<读取命令>'; <读取命令>; } > "${TMPDIR:-/tmp}/claude-sources/<仓库目录名>/<短名>.md"
    ```
    读取命令取原始内容：钉钉文档按 `dws` skill 取出 `markdown` 字段，远端仓库文件用 `gh api` / `glab api` / `git show`，网页优先取站点的 md 或纯文本源（如 raw 文件地址）。只有 HTML 时，在读取命令后接这段去标签管道再存 `.txt`——回合末逐字核对不认 HTML 标签与实体，`到期前<strong>一天</strong>` 摘成「到期前一天」会被判找不到原文：
    ```bash
    curl -sL '<网址>' | python3 -c 'import html,re,sys; t=re.sub(r"(?is)<(script|style)\b.*?</\1>","",sys.stdin.read()); sys.stdout.write(html.unescape(re.sub(r"<[^>]+>","",t)))'
    ```
  - 不用 `Write` / `Edit` 写快照、不手改快照：手一碰就成了你的文字。词条的回合末核对把本轮 `Write` / `Edit` 过的出处文件判为不算原文；回复正文括注的出处若是 `claude-sources/` 下本轮 `Write` / `Edit` 过的快照，同样打回。
  - 扩展名按第二行起的正文取：md 存 `.md`，去过标签的网页与其余纯文本存 `.txt`。接口返回 JSON 信封时先取出正文字段再存，不存整个信封。
  - 位置：系统临时目录下 `claude-sources/<仓库目录名>/`，与 `claude-wiki/` 同根；文件名 ASCII kebab-case。同一来源已有快照就复用；要最新内容时重新读一遍覆盖。
- **找不到原文**：不建词条、不写释义，原词后括注「（未找到出处）」。读者确实需要你的理解才能往下读时，那是主线内容：写在正文，按 3.4 标「推断」并写依据，受回合末出处审查——不要把它包装成释义放进链接。

### 先分主线与旁支

**主线**是用户这一轮要的东西：他问的问题的答案、要他拍板的事、他要知道的结果。主线在正文里讲透，不外推到词条——主线挪进链接，正文就空了。主线里你的分析与判断照 3.4 写，不受「只摘原文」限制。

**旁支**是读懂主线要用到、但本身不是用户在问的东西。旁支里读者可能卡住的点，按本节处理：

- 名词、概念、内部代号、编号（读者对本项目零上下文，见 3.9）；
- 压了好几层信息的一句话，如「按 hook-restraint 只做注入」——读者得先知道 hook-restraint 是什么、注入和拦截差在哪；
- 读不懂的标题或小节名；
- 待拍板问句与选项里点名的事项（如「一期不做：评估 Plugin、定时催办……」）——用户不看详细说明就答不了；
- 有原文、但散在几处，一个链接接不全的内容。

### 三级出口：按序取第一个命中的

| 情形 | 正文写法 | 链到 |
|---|---|---|
| 有一处原文说得清（本机文件某行、文档某节；远端内容的快照某行） | 原词挂链接，链接后括注摘自那一处的原文片段，加「」 | 那一处：`file://` 绝对路径加 `#行号`（远端内容链快照） |
| 原文散在多处，一个链接接不全 | 同上，括注摘其中最贴切的一句 | 词条文件（把几处原文逐条摘进去），链接不带 `#` |
| 在上面「找的范围」里找不到原文 | 原词后括注「（未找到出处）」 | 不挂 |

括注的原文片段让读者不点链接也读得通这句话（与 `devkit-readable-citations` 的「自足」一致）；片段太长时截短，不改写成白话。

**「说得清」指链到定义，不是链到提到它的地方**（用户 2026-11-23 指出：一个术语被链到设计文档开头变更记录里的一句，那句只是用到了这个词，定义在同篇后半）：
- 算定义：术语表那一行；「X 是 / X 指 / X 即 / **X** =」开头的句子；以 X 为标题的小节或表格行；协议、规范里给 X 列字段与规则的那一处。
- 不算：变更记录、编制说明、目录、待办与评审意见，以及任何只是把 X 当现成概念用的句子。
- 找法：grep 出全部命中后逐条挑定义句，不取第一个命中——文档开头常是变更记录，第一个命中多半只是提到。
- 文档里的定义是转引别处的（「XX 原文：……」）时，链到被转引的源头并读当前内容；源头改过、转引已过时，以源头为准。
- 只找到提到、没有定义：按「在上面『找的范围』里找不到原文」处理，写「（未找到出处）」。

正文形态：

```
一期不做：
- [评估 Plugin](file:///abs/repo/docs/kit-design.md#212)（「给作答打分的规则包」）
- [定时催办](file:///abs/tmp/claude-wiki/kit/scheduled-reminder.md)（「到期前一天自动提醒负责人」）
- 学分兑换（未找到出处）
```

链接标签写原词本身，不必写成 `文件名:行号`。

**每次出现都挂**（用户 2026-11-21 追加，原话：「不要只在第一次出现时添加编号 而应该是像wiki网页一样 所有出现这个词的地方都可以点击」）：一个词在本条回复里挂过链接，它在本条回复里每一次出现都挂同一个链接——列表、表格、括号、小标题、行内代码里单独写这个词都算；括注原文只在第一次给。回合末由 stop-audit 机械核对：挂过本机链接的标签（及去掉 `:行号` 的文件名）在别处裸写就打回；围栏代码块与命令内部不算。

### 不挂的情形

- 主线本身。
- 用户自己说过的词。本会话前面挂过链接或建过词条的词照样挂，复用原链接，只是不再括注原文。
- 懂开发就懂的通用技术词（HTTP、索引、事务）。
- 代码块、命令行内部。
- 用户当轮说「直接说」「别建词条」。

### 词条文件

- **位置**：系统临时目录下 `claude-wiki/<仓库目录名>/`（macOS / Linux 取 `$TMPDIR`，未设则 `/tmp`；Windows 取 `%TEMP%`），与 `devkit-tool:show-me` 的 `claude-diagrams/` 同根。不写进仓库：它是回复的附注，留在工作区会弄脏 `git status`。拼链接前先跑一次 `echo "$TMPDIR"` 取真实绝对路径，不编路径。
- **一词一文件**：文件名用 ASCII kebab-case（如 `scheduled-reminder.md`；中文与空格进 URL 要转义，容易断链），标题写原词。不用「一份文件多节、靠行号定位」：后面插进一节，前几轮回复里的行号链接就全部错位。
- **链接不带 `#`**：词条是给人看渲染效果的 md，不带 `#` 才由系统默认 md 应用渲染打开（同 `devkit-clickable-paths` 的例外条款）。
- **用 `Write` / `Edit` 写**，不用 Bash heredoc：回合末核对只认这两个工具写过的词条。
- **先查再写**：写前 `ls` 该目录。同一个词已有词条就复用；原文变了就原地改；同一概念只留一个词条（3.11 同一概念不换词）。
- **骨架**：除下面几种行，词条里不出现任何你自己写的句子。

```markdown
# <原词>

> <原文逐字摘录，可截短、可用「……」删节>
—— [<文件名>:<行号>](vscode://file/<绝对路径>:<行号>)

> <另一处原文>
—— [<文件名>:<行号>](vscode://file/<绝对路径>:<行号>)

## 未找到
- <找过但没找到原文的方面，如「谁负责维护」>

## 相关词条
- [<原词>](./<文件名>.md)

<!-- 写于 YYYY-MM-DD，会话主题：<一句> -->
```

  - 每段摘录紧跟一行出处，行号是摘录第一句所在的行；出处链接用 `vscode://file/绝对路径:行号`（落盘 md 一轨，同 `devkit-clickable-paths`）。
  - 摘录按读者理解的先后排，排序就是你唯一的编辑权。
  - 「未找到」「相关词条」两节没有内容就整节不写。
- **篇幅一屏以内**（约 40 行）。超了说明它是几个词条，拆开互链。
- **回合末核对**（stop-audit 机械比对，不经模型）：本轮用 `Write` / `Edit` 写过的词条，逐行查骨架之外有没有自写句子；每段摘录去掉 markdown 标记与空白后，按「……」切开的每个片段都要在出处文件里逐字找到，且第一段落在所注行号附近；片段短于 4 个字的不算摘录；出处文件本轮被 `Write` / `Edit` 过的不算原文。不合格时打回一次，按 reason 改词条或删掉。
- 讲解命中每轮注入「画图」的条件时，词条里不放自画的图：图也是加工。原文里有图就链过去。
- 一次要写多个词条时，同一条消息并发写完。

### 与其他规则的衔接

- **豁免**：词条文件是回复的附注，不是文档——不做 md 受众判定、不调 `devkit-tool:tech-doc`、不进 3.12 的改动清单（它们已经以链接出现在正文里）。
- **沉淀**：词条摘的原文本就在项目里，不需要沉淀；某个词在项目里根本没有定义（只能写「未找到出处」）而又反复出现时，在回复末尾提一句「X 在项目里没有定义，要我起草一段补进 `<项目里的文档路径>` 吗」，用户同意再写。
- **3.3 问法**：问句与选项里点名的事项按本节挂链接并括注原文片段；回复自己给出的选项（a / b / c 的做法、代价）写在正文，不外推。回合末链接审查只查这一条（点名事项 ≥3 项且一项链接都没有）；本节其余情形只靠注入与上面的词条核对。
- **3.3「业务词当场解释」**：括号里的释义同样摘原文；找不到写「未找到出处」。
- **解释类回复的「代号翻译」**：正文里先写的业务含义是主线讲解，按 3.4 分强度写，不受本节约束；括号里注的是原名，不是释义。代号本身需要定义时，按本节挂链接、括注原文。
- **篇章连贯「渐进披露」**：挂的链接按本节取落点。
- **在 Codex 里**：词条照写，正文里的链接改成 inline code 绝对路径（Codex 只把 inline code 里的路径识别成可点击，同 show-me）。
