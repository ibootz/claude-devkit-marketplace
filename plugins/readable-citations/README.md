# readable-citations — 引用别处的章节，要让人不点也读得懂

AI 写文档时爱写「具体判据见 working-discipline §5.2」。这句话对读者几乎没有信息量：
不知道那一节讲什么、不知道值不值得点开、点也点不动（它只是一段普通文本），而且
**过一阵子那个编号还会漂**——中间插了一节，§5.2 就指向别处了，链接不会报错，只会静默指错。

这个插件每轮注入一段写作规约，把引用改造成**自足**的形态：读者不点链接也读得懂这句在说什么，
想点的时候又点得动。

## 效果

改前：

> 具体判据见 working-discipline §5.2。

改后：

> 三档模型怎么选见 [working-discipline · §5.2 模型档位](../working-discipline/SKILL.md#52-模型档位)
> （sonnet 是默认档，opus 用于跨层追根因，fable 仅在 opus 跑两轮无进展时启用）——这是派 agent
> 的**前置条件**，定档之后才谈得上写 prompt。

四处变化，各自解决一个具体问题：

| 变化 | 解决什么 |
|---|---|
| 编号后带**标题原文**（`§5.2 模型档位`） | 编号漂移后标题仍可全文搜索找回 |
| 括号里一句**20 字提要** | 读者当场判断值不值得点进去 |
| 链接可点 | 想深入时一下就到，不必复制路径切窗口 |
| 写明**引用关系**（前置条件 / 反例 / 详细版 / 相反做法） | 读者知道这条引用与正文是什么关系 |

还有第五条，也是最省读者事的一条：**被引章节的结论只有一句话时，直接抄进正文**，
引用退化成溯源标注。多数引用其实不必存在。

## 链接形态按落点分两轨

这两轨不能混用，混了就是死链——而死链不报错，点了没反应而已。

| 落点 | 形态 | 为什么 |
|---|---|---|
| **对话正文**（终端里说的话） | `[SKILL.md · §5.2 模型档位](file:///abs/path/SKILL.md#128)（提要）` | iTerm2 对 `file:` scheme 且带 `#` 片段的链接套用 Semantic History 规则，cmd+click 直达编辑器对应行。与 `clickable-paths` 插件同一套机制，需配 Semantic History（见那个插件的 README） |
| **落盘 md**（写进文件的文档） | `[working-discipline · §5.2 模型档位](../working-discipline/SKILL.md#52-模型档位)（提要）` | 文档 commit 后会被别人、别的机器、GitLab 网页读到，`file:///Users/zhangq/...` 在那些地方全是死链。相对路径在 VS Code 预览与 GitLab 网页里都能跳 |

## 锚点怎么算（算错就是静默死链）

三步：**转小写 → 删去标点 → 空格转 `-`**。

这套算法在 VS Code 里由 `githubSlugifier` 实现，源码注释写明抄自 `Flet/github-slugger`
（那个库的自我定位就是复刻 GitHub 网页的行为），GitLab 17.0+ 换用的 `comrak` 引擎
`Anchorizer` 规则与之在「汉字保留、中文标点删除、空格转 `-`」这三点上一致。

下表三行是把 VS Code 里那段正则原样抠出来、用 `node` 实际跑出来的结果，不是推断：

| 标题原文 | 锚点 |
|---|---|
| `## 三、动手步骤` | `#三动手步骤` |
| `## 五、Agent 工具派发子代理` | `#五agent-工具派发子代理` |
| `## 2. 何为「一个功能单元」` | `#2-何为一个功能单元` |
| `### 5.2 模型档位` | `#52-模型档位` |
| `### 5.2 模型档位（三档从低到高 · 无 haiku 档）` | `#52-模型档位三档从低到高--无-haiku-档` |

**坑一：中文标点直接消失，不留任何替代字符。** 所以 `五、Agent` 里顿号没了之后，
「五」和「agent」是**直接粘连**的——那一行里唯一的 `-` 来自 `Agent` 与 `工具` 之间
原文真实存在的那个空格。凭直觉写成 `#五-agent-工具派发子代理` 就是死链。

**坑二：完整标题常会产出连续多个 `-`，那是正常的，不要手动合并。** 上表最后一行里
`·` 被删除后，它左右两个空格各自转成 `-`，于是出现 `--`。真实的章节标题往往带
`（…）`、`·`、`—` 这类修饰，锚点因此比想象的长且带连字符串。

**坑二有个未堵死的口子**：GitLab 官方文档写明「Heading link generation changed in
GitLab 17.0」——旧版（Redcarpet）会把连续 `-` 合并成一个，17.0 起换 `comrak` 引擎后
不再合并。所以标题里出现连续 `-` 时，锚点在 VS Code 与**旧版**自建 GitLab 上会不一致。
公司自建实例（`git-inner.yunxuetang.com.cn`）跑的是哪一侧未核实（需内网登录）。
规避办法很简单：**引用时优先挑不含 `·` 与括号的标题层级**，或干脆引用上一级标题。

## 三种阅读场景的实际表现（有一格是退化的，别当没有）

| 你在哪读 | 点击相对链接 + 中文锚点会怎样 |
|---|---|
| **VS Code 编辑器**里 Cmd+点（读 md 源码，最常用） | 打开目标文件并**精确定位到该标题** |
| **GitLab / GitHub 网页** | 浏览器原生 fragment 跳转，会做百分号解码，**能定位** |
| **VS Code Markdown 预览**里点 | **打开目标文件，但停在顶部不定位** |

第三格是 VS Code 自身的实现所致：预览 webview 加载时把 fragment 做了 `encodeURIComponent`，
再拿编码后的字符串去比对标题元素**未编码**的 `id` 属性，两者永不相等，于是不滚动。
纯 ASCII 锚点凑巧能对上（编码是恒等变换），一旦锚点里有中文就必然对不上。

**核实深度声明**：上表第一、三行是对 VS Code 1.132.0 已发布源码做静态调用链追踪得出的，
**没有在真实 GUI 里点击实测**（探查环境无显示设备）。锚点算法那张表是真实执行过的程序输出，
可信度更高。要把第三行当强约束用之前，值得人工点一次交叉验证。

## 与 clickable-paths 的分工

两个插件都在让引用可跳转，但管的东西不重叠，同时装不冲突：

| | clickable-paths | readable-citations（本插件） |
|---|---|---|
| 管什么 | 提到**文件**时的路径 | 引用 **md 文档的章节** |
| 作用范围 | 只管对话正文，明文把「写进文件的 md」排除在外 | 对话正文与落盘 md 都管 |
| 形态 | `[文件名:行号](file:///绝对路径#行号)` | 上表两轨 |

判据很简单：**引用的是一份 md 文档里的某一节** → 本插件；**提到一个源码文件的某一行**
（`.js` / `.py` / `.java`）→ clickable-paths，锚点对那些文件无效。

## 为什么挂了两个事件

`UserPromptSubmit` **只触达主会话**——它的语义是「用户在交互界面提交了一次 prompt」，
而子代理由 `Agent` / `Task` 工具编程派发任务字符串，不存在这个动作，注入到不了它们。

落盘文档恰恰大量由子代理写（sdlc-writer、各类 keeper、做实现的 general-purpose 都在写 md）。
只挂 `UserPromptSubmit` 会漏掉产出文档的主力，且**没有任何报错**——hook 正常执行、
正常输出、退出码 0，只是那段文本永远不出现在需要它的上下文里。

所以本插件双挂 `UserPromptSubmit` + `SubagentStart`，共用同一个脚本，输出的
`hookSpecificOutput.hookEventName` 按入参回声（写死任一个会让另一路静默失效）。
判据与实证见仓内 `.claude/rules/project/hook-restraint.md` 的「注入类 hook 的事件落点」一节。

## 注入了什么

约 1056 字符，主会话与每个子代理各一份。要点：

1. 结论只有一句就内联，引用退为溯源标注；
2. 带标题原文，不写光秃秃的编号；
3. 括注 20 字提要；
4. 写明引用关系，必读的内联、延伸的才给链接；
5. 两轨链接形态（见上表）；
6. 锚点三步算法与两个坑（见上文「锚点怎么算」）；
7. 不触发的场合：引用源码文件保持原路径写法、同文档内自引用直接写标题、代码块与 commit
   message 与提交给外部系统的内容一律原样。

纯注入类 hook，不拦截任何工具调用，失败模式只是「多占了约 1056 字符上下文预算」。

## 关闭

```bash
export READABLE_CITATIONS=off     # 或 0 / false
```
