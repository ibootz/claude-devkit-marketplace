# 头脑风暴：把未知挖出来

目标取自调用参数；没给参数，就取当前对话里正在讨论的任务。

**未知**是用户脑中的意图与 Claude 手上的上下文之间的差距。本 skill 的产出是收敛后的结论摘要，不是实现：未知收敛前只做可供反应的原型，不写正式代码。

## AI 自行调用时

本次调用是你按 description 的判据自己发起的（不是用户敲的命令）时，在下文流程上叠加四条；委派 superpowers 时同样叠加：

1. 第一句告诉用户：任务做到哪一步、撞上了哪些未知、它们会改变什么。
2. 只挖挡住当前这一步的未知。与当前这一步无关的疑问写进收尾摘要的「仍待定的点」，不展开。
3. 没有人能回答时，不发起访谈，也不停下等用户反应。判据：你是子代理，或已知本次运行无人值守（如 `claude -p` 单次运行、定时任务）。此时列出未知，每条附默认答案与理由、标「待确认」，写进回执或最终输出，交回调用方。
4. 出完收尾摘要，回到被打断的任务，按已澄清的决策接着做。

## 先委派 superpowers（已安装时）

可用技能列表里有 `superpowers:brainstorming` 时，用 Skill 工具调用它，把目标原样传入、按它的流程走，同时叠加两条约束：可视化产物做成假数据的单 HTML 原型、给多个方向；提问先问回答会改变架构的问题。没有这个技能就按下文执行。

## 四种手法

按用户处境挑，可组合。多个都适用时按「盲点扫描 → 发散 → 收敛」的顺序走，前一步的产出作为后一步的输入；参考在用户拿出样例时随时插入。

| 用户处境 | 手法 |
|---|---|
| 陌生领域，不知道该问什么 | 盲点扫描 |
| 说不清要什么、但看到就知道好坏（UI、布局、文案、可视化），或范围拿不准 | 发散 |
| 知道哪里没想清，有影响架构的模糊点 | 收敛 |
| 说不清，但手上有现成样例或参考实现 | 参考 |

### 盲点扫描

1. 上下文里缺用户背景（已知什么、目标是什么）时先问一句；已有就跳过。
2. 扫相关代码与领域知识，列出用户多半没意识到的未知：隐含约束、历史决策、常见坑、好坏标准、可选方案。
3. 每条讲清它对本任务为什么重要、忽略会怎样。
4. 结尾给一份「现在可以问的更好的问题」。

### 发散

- 同一产物给 3–4 个风格迥异的方向。可视化产物做成单独的 HTML 文件、用假数据，不接后端。
- 范围拿不准时，搜代码库列出多个可介入点，从最省成本排到最有雄心，让用户挑。
- 指出用户可能漏掉的高价值方向，以及范围偏窄或偏宽之处。

产出后停下，等用户反应再继续。

### 收敛（访谈）

1. 一次只问一个问题，等回答后再问下一个。
2. 先问回答会改变架构、技术选型、数据模型的问题；纯偏好、可后置的细节放后面或跳过。
3. 每问附上倾向的默认答案与理由，让用户可以只回「就按你说的」。
4. 能从已有背景推断的，直接采用并在摘要里注明，不再问。

### 参考

1. 向用户要源码级参考：源码比截图、文档带的结构细节多得多。
2. 读完先复述理解到的语义（行为、边界、取舍），与用户对齐。
3. 在当前项目复刻语义而非逐行翻译；参考所用语言或框架带来的差异，不当成行为差异搬进来。

## 收尾

剩下的问题都不再改变架构或范围时，主动停下，输出结论摘要：

- 已澄清的决策
- 仍待定的点
- 建议的下一步（实施规划与拆任务交给规范驱动流程，如本市场的 devkit-spec）
