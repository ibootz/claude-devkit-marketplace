# 看懂一个新事物

把一个**新事物**变成一组从不同角度切入的专业文章，再用一次**检验检查点**确认使用者真的懂了。
新事物指对**这个使用者**是新的东西，不要求对外界也新。

主会话只做三件事：开工问齐、写**事实底稿**、收尾回看与检验。查资料、写文章、画图都交子代理并行做——这是本 skill 控制耗时的主要手段，实测单个子代理串行调研 45 个理论跑了 122 分钟，同样的活拆开并行才能落进下面的档位目标。

## 档位

开工时让使用者选一档，默认标准。数字都是初值，评测后按运行记录校准。

| 档 | 篇目 | 自查 | 图 | 目标 |
|---|---|---|---|---|
| 速览 | 不论规模都出合并结构 3 篇 | 不查；缺的标【空白】并写怎么核实 | 每篇一张主图，其余标「待补」 | 首份可读产物约 30 分钟，整组约 40 分钟 |
| 标准 | 按规模定篇 | 3 路并行，每路 ≤8 个来源、≤15 分钟 | 随篇 | 首份约 40 分钟，整组约 60 分钟 |
| 深入 | 同标准，可加教程篇 | 每路 ≤15 个来源、≤30 分钟 | 随篇，可加演练 | 开工时按规模报预估 |

**首份可读产物**指导读、本质两篇写完、使用者能开始读的时刻。**整组**指全部文章与图交付，不含使用者在检验检查点答题的时间。

**降级**：某一段超出预估一半时，按固定顺序减量——先停自查、缺的标【空白】，再把没画完的图标「待补」——并在运行记录里写明降级了什么。

## 产物目录

```text
<落点>/<新事物名>/
├── run-log.md          运行记录：档位、预估、各阶段起止时刻、降级记录
├── 00-sources.md       资料清单、冲突清单、待问清单
├── 01-fact-base.md     事实底稿
├── 10-guide.md         导读
├── 20-essence.md       本质
├── 30-mechanism.md     机制（大题按子系统拆成 30-mechanism-<子系统>.md）
├── 40-coordinates.md   坐标
├── 50-tutorial.md      教程（使用者要上手时才出）
├── 70-integration.md   融会贯通
├── checkpoint.md       检验记录
├── figures/            每张图一对：<篇号>-<主题>.excalidraw 与同名 .png
```

**交付格式选 HTML 时**，各篇直接写成正文片段 `<篇号>-<篇位>.html`（不写 `.md`），收尾合成一个 `<落点>/<新事物名>.html`，图与 Excalidraw 源稿都内嵌在里面，读者只拿这一个文件。片段写法见 `devkit-tool:tech-doc` 的 `references/html.md` 第七节「多篇合成一个 HTML」。产物目录仍保留：它是过程资产，续跑与 `new-thing-leverage` 要读；读者不需要它。

合篇时文件取较小的篇号、名字并列：`10-guide-essence.md`、`30-mechanism-coordinates.md`。
**最小集**是 `00-sources.md`、导读、本质、机制四份（合并结构下就是 `00-sources.md`、`10-guide-essence.md`、`30-mechanism-coordinates.md`）。
落点默认当前目录，使用者指定优先；产物不 `git add`、不提交。目录里已有产物时按已有的续跑；使用者点名只做某一步就只做那一步。

## 第 1 步：开工

1. 一次问齐下面几项，之后不再为补信息停顿。使用者已经在请求里给了的不再问。
   - 新事物是什么，资料在哪（本地目录、文件、在线文档、代码仓都算资料）；
   - 使用者背景：做什么的，在相邻领域已经会什么——分「可借力」「可能误导」两类记下；
   - 一句话目的：他想借这个新事物取得什么进步（**进步陈述**），篇目取舍以这句为准；
   - 关注点：最想先弄清的一两件事；
   - 落点与档位；
   - 交付格式：md（默认），或单文件 HTML——各篇直接写 HTML，最后合成一个图片内嵌、双击即开的文件，适合发给不看仓库的人。两种格式的取舍见 `devkit-tool:tech-doc` 第零步。
2. 无人值守（子代理、headless、使用者不在）时不发问：每项取最保守的默认值，档位取标准，格式取 md，写进 `run-log.md` 标「默认，待确认」。
3. 写 `run-log.md`：档位、交付格式、**期望结果**（读完能做到什么）、**怎么算达到**（检验检查点要过什么）、预估时长、开工时刻。把预估一句话告诉使用者。
4. 新事物是公开的（开源项目、公开标准、公开理论）且档位不是速览时，立即派自查子代理，与第 2 步同时进行。「资料优先」是出处的排序，不是先后顺序。

**完成判据**：五项都有值或标了默认；`run-log.md` 写了期望结果与预估；该派的自查已派出。

## 第 2 步：资料清点与自查

读 [references/sources.md](references/sources.md) 再动手：资料清单的列、冲突预检的三样比对、四种来源标签、自查子代理的派发说明都在里面。

- 资料多（超过 10 份或超出一次细读的量）时按主题派子代理摘要，主会话回读关键原文核对；跨资料的冲突比对由主会话做。
- **唯一的停顿点**：资料之间在核心结论上冲突、按 references 里的判据定不了以哪份为准时，列给使用者拍板。其余冲突按判据自定，写明依据。

**完成判据**：每份资料都在清单里，读不到的标了原因；每条冲突两边的原话与出处齐全；自查各路已交回或已按时限截停。

## 第 3 步：写事实底稿

主会话亲手写 `01-fact-base.md`，它是各篇子代理唯一共同的底本，各篇的术语、数字、出处都以它为准。格式见 [references/fact-base.md](references/fact-base.md)。内容四块：

1. 术语表：每个术语的白话定义、原名、出处；同一概念的不同叫法合成一行。
2. 关键事实：每条带来源标签与出处。
3. 篇目分工：本次出哪几篇、每篇回答什么问题、目标理解层级、核心概念在哪两篇里重访。篇位与合拆规则见 [references/articles.md](references/articles.md)。
4. 图规约：本组文章统一的配色、字体风格、图例约定，以及每篇要出哪几张图。

**完成判据**：任一篇的作者只读事实底稿与本篇分工，就能开写，不必再读原始资料全集。

## 第 4 步：并行写各篇

按 [references/fact-base.md](references/fact-base.md) 里的派发说明，每篇派一个子代理，同一条消息里并发派出：

- 第一批：导读、本质、机制（拆篇时每个子系统一个）、坐标、教程。
- 第二批：融会贯通。它要引用前面各篇，等第一批交回再派。

每个子代理自己写正文、自己按图规约画 Excalidraw 图并看 PNG 修图，正文直接写进文件，回执只报路径与要点。
导读、本质交回后立即告诉使用者可以开始读，附文件链接，不等整组。交付格式是 HTML 时，用收尾那条命令只列这两篇，先合成一版 HTML 给他读。

**完成判据**：篇目分工表里的每一篇都已落盘；每张计划内的图要么有 PNG，要么原位标了「待补 Excalidraw 图」与原因。

## 第 5 步：主会话回看

1. 一致性：各篇的术语、数字、交叉引用与事实底稿一致；不一致的改回事实底稿的说法。
2. 逐张看图：Read 每一张 PNG，图例与配色统一，不清楚的退回该篇子代理重画或自己定点改。
3. 覆盖：按 [references/articles.md](references/articles.md) 末尾的 Merrill 五原则检查表逐条核对，缺哪条补哪条。
4. 零上下文检查：按第 1 步记下的使用者背景，每个术语首次出现处有白话解释。

**完成判据**：四项各写一行结论进 `run-log.md`，发现的问题都已改掉或写明为何不改。

## 第 6 步：检验检查点

读全部文章之后做一次，规程在 [references/checkpoint.md](references/checkpoint.md)。
这一步不能省：使用者读完 AI 写的文章会觉得自己懂了，而这种流畅感不等于学会，只有让他自己讲出来、答出来，盲区才会暴露。
使用者要跳过时先劝一次，讲清上面这个理由；仍坚持就跳过，`checkpoint.md` 写「未检验，用户坚持跳过」。
速览档同样要做，题量取下限。

**完成判据**：`checkpoint.md` 有作答记录与逐条反馈，暴露的盲区已回填进对应文章；或写明了跳过。

## 收尾

交付格式是 HTML 时，第 6 步回填完盲区之后再合成，保证 HTML 是最终版：

```bash
uv run '<本 skill 目录>/../tech-doc/scripts/html_pack.py' assemble \
  10-*.html 20-*.html 30-*.html 40-*.html 50-*.html 70-*.html \
  -o '../<新事物名>.html' --title '<新事物名>'
```

在产物目录里跑；先 `ls` 核对，列表里只写实际存在的文件（合篇、没出教程时去掉对应项，zsh 下匹配不到的通配会让整条命令报错），顺序就是读者的阅读顺序。`run-log.md`、`00-sources.md`、`01-fact-base.md`、`checkpoint.md` 是过程记录，不进 HTML。退出码与警告的处理见 `references/html.md` 第五节「打包与检查」，处理到警告为 0 条。

写 `run-log.md` 的结束时刻，然后告诉使用者：

- 产物目录与各篇一句话提要；交付格式是 HTML 时只给那一个 HTML 文件，并说明产物目录是过程资产、续跑与 new-thing-leverage 要用；
- 待问清单的条数与最关键的 3 条；
- 实际耗时与档位目标的差，降级过什么；
- 第 1 步的进步陈述涉及把新事物接进他自己的系统、或把他的业务接进新事物时，提示下一步用 `new-thing-leverage`。

## 画图

- 一律 Excalidraw：调 `devkit-excalidraw-diagram:excalidraw-diagram`，产出 `figures/<篇号>-<主题>.excalidraw` 与同名 `.png`，md 文章里用 `![图注](figures/<篇号>-<主题>.png)` 引 PNG；HTML 片段里写 `<img src="figures/<篇号>-<主题>.png" alt="图注">`，合成时 PNG 与源稿一起内嵌。状态图、时序图、流程图同样用 Excalidraw，整套产物里没有 mermaid 代码块。
- 先表后图：图上每个节点与每条边都能在本篇的表格或正文里找到出处。
- 渲染后核对 PNG 的修改时间晚于本次渲染开始；渲染命令的输出原样看完，不接 `tail`、`head`。实测渲染会因页面加载超时静默失败，PNG 停在旧版，截断输出会把报错一起截掉。
- Excalidraw 插件未安装或渲染跑不通时，原位放一个文本箭头图代码块，标「待补 Excalidraw 图」并写原因。
