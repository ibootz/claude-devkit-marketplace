# 文档配图细则

SKILL.md 第四步的展开：选什么图、每张图怎么检查、全篇怎么统一、画完怎么确认。单张图的载体与落点仍按 `devkit-tool:show-me` 第二、三节定。

---

## 一、按要回答的问题选图

| 要回答的问题 | 图 | 依据 |
|---|---|---|
| 有哪几块、谁和谁有关系 | 系统上下文图或分层框图，≤7 个方框 | 【有出处】C4：系统上下文图面向所有人，含非技术人员 |
| 某一块内部由什么组成 | 容器图或组件图，每个子系统一张 | 【有出处】C4 |
| 一次请求谁先调谁 | 时序图，步骤编号 | 【判断】 |
| 状态怎么变化 | 状态机图 | 【判断】 |
| 现在怎样、要改成怎样 | 改前、改后两张，同布局同配色 | 【判断】 |
| 多个对象比较属性 | markdown 表格，不画图 | 【判断】 |
| 什么条件下算什么 | 决策树 | 【判断】 |
| 事件先后 | 时间线表格，时刻带时区 | 【判断】 |

时序图超过约 6 个参与方或 15 步时，先放一张 4 到 5 个方框的简图讲主干，再给详细图。【推断】依据 Google「一图一段」。

---

## 二、每张图的检查细则

1. **图注先行**。动笔画图前先写图注，说清这张图回答什么问题；写不出图注说明这张图没有单一要点，拆开。【有出处】Google *write the caption first*（原文是 often helpful 的建议）。图注写成「图 N 说的是：……」放在图前，让读者先知道看什么。【判断】
2. **信息量不超过一段文字**，超了就画一张全景，再给每个子系统一张。【有出处】Google；原文另一判据是：解释这张图不该需要超过五条要点。落到数量上，方框不超过 7 个、全景图建议 ≤6。【判断】
3. **每条箭头标注含义**：动词或数据名，如「调用」「推送任务」「回填结果」。两条同起止点的边合成一条两行标签。【有出处】C4 审查清单
4. **标题与图例**。第一张图下放一行图例：每种颜色代表什么角色、虚线代表什么、缩写全称。后续图沿用，不再重复。【有出处】C4
5. **用标注引注意力**。把读者该看的那处直接标在图上，如「直连外部」「← 你问的在这」。【有出处】Google callouts
6. **图后逐块解释**。图之后每个方框各一段：它是什么、在这张图里做什么。【有出处，二手】Mayer 就近原则
7. **删掉无关节点**。判据：删掉它，图注那句话是否仍成立；成立就删。【有出处，二手】Mayer 去冗余原则

## 三、全篇统一

同一篇文档的所有图用同一种风格（都 mermaid，或都 Excalidraw 同一风格）、同一字体、同一套**按角色**的配色。按角色配色意味着同一个角色在每张图里颜色相同，读者看一次图例就能读懂后面所有图。【判断】

默认角色配色（取自 Excalidraw 调色板，mermaid 用 `classDef`、Excalidraw 用元素属性）：

| 角色 | 填充 | 描边 | 用于 |
|---|---|---|---|
| 本方服务 | `#a5d8ff` | `#1971c2` | 本项目自己的服务、模块 |
| 平台 / 中间件 | `#ffec99` | `#f08c00` | 共用平台、队列、网关 |
| 外部 | `#ffc9c9` | `#e03131` | 第三方、外部厂商 |
| 目标 / 新增 | `#b2f2bb` | `#2f9e44` | 方案要建成的部分 |
| 范围外 / 废弃 | `#dee2e6` | `#495057`，虚线 | 不在本次范围、待下线 |

分组框统一灰色虚线、透明填充，不抢方框的颜色。

mermaid 写法：

```text
classDef svc fill:#a5d8ff,stroke:#1971c2
classDef plat fill:#ffec99,stroke:#f08c00
classDef ext fill:#ffc9c9,stroke:#e03131
classDef target fill:#b2f2bb,stroke:#2f9e44
classDef out fill:#dee2e6,stroke:#495057,stroke-dasharray:5 5
api[订单服务]:::svc -->|推送任务| mq[消息队列]:::plat
```

## 四、选载体

- **默认**：按 `show-me` 调 `devkit-excalidraw-diagram` 出 Excalidraw 图，`.excalidraw` 与 PNG 放在文档旁的 `figures/` 目录，文档里引 PNG。PNG 在 GitLab / GitHub、Typora、钉钉等在线文档里都能直接显示。【判断】
- **未安装 `devkit-excalidraw-diagram` 或渲染跑不通**：mermaid 源码写进 md；要发布到不渲染 mermaid 的平台时，先导出 PNG 再引用，源文件 `.mmd` 同放 `figures/`。
- 一次性给人看、看完即弃的视觉讲解才用 HTML。

---

## 五、渲染与发布的坑

- **中文标签被拦腰折行**：mermaid 自动折行按宽度切，会把一个词切成两半。长标签用 `<br/>` 手动断行。
- **转 Excalidraw 时**（`@excalidraw/mermaid-to-excalidraw`）：
  - 子图 id 不能叫 `before` / `after`，否则报 `SubGraph element not found`；改成 `sgBefore` / `sgAfter`。
  - 两条同起止点的边只保留一条；合并成一条两行标签。
  - 转换器会给长标签自动折行，中英文混排时可能丢空格；出图后看一遍文字。
- **粗体不生效**：`**标签：**正文` 这种结束 `**` 前是全角标点、后面紧跟汉字的写法，按 CommonMark 的右侧定界规则不算结束符。写成 `**标签：** 正文` 或 `**标签**：正文`。
- **发布到在线文档平台后必须回读**：mermaid 可能显示成源码卡片、需要手动切成「只显示图表」；导出稿里的 `&#42;` `\+` 等转义要确认线上是否也这样显示；图片插入后数一遍图片块数量，防止重试造成重复插入。
