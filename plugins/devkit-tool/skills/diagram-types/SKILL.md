# 图型选型

画图之前，先把候选集放大到全人类用过的图型，再按读者要看到的东西收窄到一种。**开阔视野是扩大候选集，不是画得更花**：一张表或一棵缩进树就能讲清的，选型结论就是表或树。本 skill 只回答「选哪种图、它擅长表达什么」，选定之后用什么工具画、画在哪里不归本 skill。

## 步骤

1. **写下读者问题**：用一句话写出读者看完图要能回答的问题，如「退款卡在谁手里」「这 8 周哪条任务链决定工期」。写不出这句就先别选图——图型由问题决定，不由话题名词决定。

2. **判信息本质，查主索引**：在下面的主索引里找到问题对应的那一行，列出 2～3 个候选，用「区分判据」一列淘汰到一个。

3. **查行业标准图**：话题本身属于某个专业领域（建筑、机械、电子电气、化工、医学、地理气象、交通调度、金融会计、语言学、服装手作、音乐体育……）时，读 [`references/cross-domain.md`](references/cross-domain.md) 对应一节，优先用该行业约定俗成的图与记号——行业读者认记号，自创画法反而增加阅读成本。软件与商业话题要对比同类细分图型（如 C4 四层、BPMN 与活动图、各类统计图）时，读 [`references/software.md`](references/software.md)。

4. **候选都别扭时查借法表**：主索引的候选都要硬套时，看下面「跨领域借法」，很多软件问题的最佳图型来自别的行业（运行图、地铁图、爆炸图）。

**完成判据**：写得出两样——一个具名图型及它编码的要素（如「泳道图：每条泳道一个角色，跨泳道的箭头是交接」）；一句「它为什么胜过次优候选」（如「选泳道不选流程图：要点是四个角色之间的交接」）。缺一样，回到对应步骤。另附一项**拓扑**，交给画图工具挑布局：分层 / 树 / 流程网 / 泳道或时间轴 / 实体关系 / 二维矩阵 / 自由空间 / 数据图表，取其一。

## 主索引：读者要看到什么 → 图型

| 读者要看到 | 候选图型 | 区分判据 |
|---|---|---|
| 系统由哪些部分组成、怎么分层 | 分层架构图、C4（上下文 / 容器 / 组件）、部署图、网络拓扑、洋葱 / 六边形 | 讲边界与外部依赖用 C4 上下文；讲运行在哪、多可用区与容灾用部署图；讲依赖方向只许向内用洋葱 / 六边形 |
| 整体拆成哪些部分、归属关系 | 功能分解树、WBS、组织架构图、站点地图、思维导图 | 每项只归一个父节点、要能逐层加总用树或 WBS；发散联想、不求互斥穷尽用思维导图 |
| 一件事按什么步骤走、在哪分叉 | 流程图、泳道图、BPMN、活动图、决策树 | 要点是角色之间的交接用泳道；有并行分叉汇合用活动图；要交给流程引擎执行用 BPMN；每步都是条件判断、叶子是结论用决策树 |
| 谁调用谁、消息的先后与同步异步 | 时序图、报文梯形图、通信图 | 关心返回、超时、激活期用时序图；关心传输时延与双方状态变化用梯形图；对象多、只要拓扑加编号顺序用通信图 |
| 一个对象有哪些状态、什么事件触发转移 | 状态机图 | 节点是「对象处于的状态」而不是「要做的动作」时就是状态机，画成流程图会把状态与动作混在一起 |
| 时间上怎么安排、怎么演进 | 甘特图、路线图、里程碑时间线、PERT / 关键路径、GitGraph、链路瀑布图 | 有依赖、要看关键路径用 PERT 或带依赖线的甘特；只讲方向不承诺日期用路线图；单次请求的耗时嵌套用瀑布图 |
| 多个对象沿同一串阶段随时间推进 | 运行图（Marey 图）、时距图 | 斜率是速度、平段是排队等待、交叉是追越；讲「批任务各阶段卡在哪」「请求穿过多服务」比甘特更直观；对象超过约 20 个时线会糊成一片，只画有代表性的几条，其余合成一条阴影带 |
| 数据长什么样、实体之间什么关系 | ER 图、类图 / 领域模型、数据血缘图、DFD、协议位域图、内存布局图 | 表与基数关系用 ER；行为与继承组合用类图；表 / 字段上下游影响面用血缘；数据在处理之间怎么变换用 DFD；按比特切报文用位域图 |
| 网状依赖、多对多关系 | 依赖图、概念图 / 知识图谱、社会计量图、依赖结构矩阵（DSM） | 边上要写语义谓词用概念图；找循环依赖、扇入扇出用依赖图；边数 >30 时节点连线必然交叉，改用 DSM（行列都是模块的矩阵） |
| 问题的原因 | 鱼骨图、故障树、因果回路图、攻击树 | 按维度归类候选原因用鱼骨；原因之间有与 / 或逻辑用故障树；原因互相强化、有反馈环用因果回路；推演攻击路径用攻击树 |
| 按两个维度定位、分类 | 四象限 / 2×2 矩阵、SWOT、Wardley 地图、商业画布、看板、RACI | 两轴都是连续量用四象限（可加气泡表第三维）；轴是「可见度 × 演化阶段」用 Wardley；行列交叉标职责用 RACI |
| 集合重叠、层级底座、逐级衰减 | 韦恩图、金字塔、漏斗图、同心圆 | 重叠区域本身有含义用韦恩；每层是下一层的子集并逐级转化用漏斗；越往上越少、越往下越基础用金字塔 |
| 用户经历什么阶段、在哪痛 | 用户旅程图、服务蓝图、用户故事地图、页面流、线框图 | 加上前后台与支撑系统用服务蓝图；按 MVP 切片排需求用故事地图；屏幕之间怎么跳用页面流 |
| 数量的比较、趋势、构成、分布、关联、流向 | 统计图表（见下一行与 software.md 第八节） | 先定要比的关系：比较→条形 / 柱状；趋势→折线（横轴是有序档位如负载档、版本，且要看走势时也算趋势）；构成→堆叠条 / 矩形树图；分布→直方 / 箱线；关联→散点 / 热力；流向→桑基 |
| 实物的形状、尺寸、空间关系 | 平立剖、轴测与爆炸图、剖视图、大样图、展开图 | 读 cross-domain.md 第九、十节 |

**常见误选**（选完对照一遍）：

- 饼图超过 5 类，或要比较相近的份额：改条形图，人眼比长度比比角度准。
- 用平均值柱状图讲分布：均值藏掉长尾与双峰，改直方图或箱线图。
- 用流程图画状态：同一个状态出现两次、箭头上写的是动作而不是事件，就该换状态机。
- 用时序图画跨部门的审批流转：时序图讲消息，职责交接用泳道。
- 依赖图画到几十条边：交叉压不下去，改 DSM 或按层只画一层。
- 一张图同时讲分层和请求路径：拆成两张，一张图回答一个问题。

## 跨领域借法

别的行业为特定问题发明的编码，常常正好适合软件与业务话题。主索引的候选都要硬套时，按读者问题对照这张表。

| 读者问题 | 借用的图型（出处） | 怎么借 |
|---|---|---|
| 多个任务 / 请求沿同一串阶段推进，哪里在排队 | 列车运行图（铁路调度） | 横轴时间、纵轴阶段，每个对象一条折线；平段即等待 |
| 几个周期性窗口要错开或对齐 | 绿波带时距图（交通信号） | 横轴时间、纵轴位置，画出各窗口的相位差 |
| 拓扑很乱、读者只关心连接顺序与换乘点 | 地铁线路图（轨道交通） | 丢掉真实位置，只留站点顺序，线条只走 45° / 90° |
| 分层架构或协议栈要逐层讲清 | 爆炸轴测图（建筑、机械） | 把各层沿一个方向拉开，层间用虚线对齐 |
| 一次请求穿过哪些层 | 剖面图（建筑） | 沿请求路径「切开」系统，只画被切到的层 |
| 总图里有一处关键细节 | 大样图 / 局部放大（建筑、机械） | 总图上圈出位置，旁边放大画那一处 |
| 少数对象占了大头 | 洛伦兹曲线（经济学） | 横轴对象累计占比、纵轴量的累计占比，曲线越弯越集中 |
| 三个部分合计 100% 的构成怎么分布 | 三元相图（土壤学） | 等边三角形三边各是一个分量，每个样本一个点 |
| 某个策略在不同输入下的得失 | 期权损益图（金融） | 横轴输入（负载、价格）、纵轴收益，折线拐点就是阈值 |
| 容量与需求怎么累计对冲 | 订单簿深度图（交易） | 两条累计曲线相向，交点即平衡点 |
| 方案拍板的依据与反驳 | 论证图谱（哲学） | 结论在顶，前提、反驳、补强分别连线 |
| 多方先后做决定、各自得失 | 扩展式博弈树（博弈论） | 每层一方决策，叶子写各方结果 |
| 多个布尔条件的组合有没有漏 | 卡诺图（数字电路） | 条件两两成轴，每格一个组合，空格就是漏掉的规则 |
| 两条链路的结果应该一致 | 交换图（范畴论） | 两条路径首尾相接成方框，标出必须相等的两端 |
| 团队或服务之间关系的好坏、强弱 | 家系图的线型编码（心理学） | 用实线、虚线、锯齿线、双线区分协作、弱依赖、冲突、强耦合 |
| 多分支交互、对话或剧情 | 分支叙事树（互动叙事） | 节点是场景，边上写条件变量，标出汇合点与结局 |
| 一次变更会扫到哪些地方 | 扫掠路径包络（交通工程） | 画出变更的影响边界，与现有结构叠在一起看 |

## 把图型再抽象一层

选型卡住时，用三个维度定位要画的图，再回主索引：

- **描述还是指令**：描述图还原已有事物（架构现状、根因、监控热力图），可以简化取舍；指令图是先有图、后有实物的契约（接口规格、施工图、部署清单、排期），每个记号都必须有确定含义，不能为好看省略。换视觉风格时，指令图只动载体层（底色、线宽、字体），记号、线型与比例保持行业规范原样。
- **给人看还是给机器读**：给人看的追求一眼读懂；要被程序解析的（BPMN XML、Gerber 文件）按格式规范画，美观让位于可解析。
- **把哪一维折进平面**：所有图都在把高维信息压进二维——时间折成斜线（运行图）、海拔折成闭合曲线（等高线）、关系强弱折成线型（家系图）。说不清要折哪一维时，回第 1 步重写读者问题。
