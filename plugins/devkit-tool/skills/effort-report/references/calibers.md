# 口径全集（D-003 基线）

> 这些口径不是通用真理，是 D-003 报告拍板过的执行口径。移植时可推翻，但推翻要留记录；不推翻就照此执行。

## 1. 时间折算

- 工作时段 08:00–19:00，每日有效工时封顶 8h，周末不计，08-07（周五请假）整日剔除
- 有效工时 = 活跃段（动作时刻 ± 活跃半径合并）与工作时段的交集，非「在线时长」
- **subagent 执行时间计入**：按其活跃段并集算进所在阶段；主会话只记派发与收回执那段时间，不重复计

## 2. 阶段切窗

- 阶段边界 = 门禁事件（gate decided_at + git commit 时刻），互不重叠、连续覆盖
- **线性窗口归属**：窗口内动作一律归本阶段。理由：流程是线性的，跨阶段微调属正常衔接，按产物锚点重判会把返工放大一倍以上
- **返工只认账本**：唯一计量口径是交付账本明确记录的门禁回退（D-003：G2/G3 回退重过 = 17.71h / 18.8%）。账本没记的跨窗动作不算返工
- 无独立工时窗口的并行段（如 fusion 收尾落在 domain Verify 期间）单独给证据行，不切窗

## 3. 两层构成与守恒

- 阶段内只分两层：**具名步骤**（能锚到本阶段流程步骤）+ **本阶段其余**（协调/检索/衔接），两层相加 = 阶段总量
- **并集口径**：任何分项（类别/桶/步骤）按各自活跃段并集独立计时，相加 > 阶段总量是结构性的（动作交替进行），不是错误。总量永远走并集
- 守恒校验两处：① 阶段合计 vs 主报告总量（差 ≤ 0.01 舍入）；② named + unnamed = 阶段 eff（unnamed 用全精度差取整，不用已舍入值相减）

## 4. 两个总量

- **94.17h**：calc 链主报告口径（含一处 0.01 的日历舍入差）
- **94.16h**：阶段合计口径（对外引用用这个保守数）
- 总量对齐（align.py apply_drop）：某阶段被移除时（D-003 的 P5 空窗，0.01h），其量从总量与三档同步扣除，全报告统一口径

## 7. 裁剪折扣纪律

- 每个折扣（如 ×0.49）必须有实证权重支撑（占比 × 可省比例逐类加权），**禁止拍一个总折扣**
- 例（C1）：定位条款 56.1%×60% + 复算条数 23.1%×50% + 跨文件一致性 7.4%×0% + 零散 11.7%×30% = 49%
- 注入方案只存在于报告中，不落仓——报告讲"如果"，不替流程做主
