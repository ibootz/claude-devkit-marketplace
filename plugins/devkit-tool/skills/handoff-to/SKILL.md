# 交接给另一个会话

接收方是**冷启动读者**：它看不到本会话的对话、工具结果和你的判断过程，手里只有你写进交接文档的内容。四个步骤都服务于一个目标——接收方只读这份文档就能接着干。

## 参数

- 第一个词：目标会话名（用户口中的叫法，不一定等于注册名）。
- 其余部分：下一会话要做什么（focus），可省。给了就按它取舍文档内容：与 focus 相关的写细，无关的一句带过。
- 没给会话名：调 `ListAgents`，把可达会话列给用户选，等用户回答后再继续。

## 1. 找到目标会话

调 `ListAgents`。输出首行 `This session is <名字> [ref]` 是本会话自己的名字，第 3 步要用；其下每行是一个可达会话，行首 `name [ref]` 就是寻址名，后面带类型标注。

按用户给的名字匹配：

| 匹配结果 | 动作 |
|---|---|
| 与某一行的 name 完全相同 | 直接用这个名字 |
| 只有一行模糊匹配上（包含关系、大小写或空格差异、中英文叫法对应） | 报给用户「你说的 X 是不是 `<注册名>`」，等确认 |
| 模糊匹配到多行，或一行都没有 | 列出全部候选，让用户选 |
| 两行 name 相同 | 发送时用 `name [ref]` 区分 |

记下目标行的类型标注：标为云端会话（cloud）或另一台机器上的 Remote Control 会话时，对方读不到本机文件，第 3 步改为贴全文。

**工具表里没有 `ListAgents`**（含在 Codex 里运行）：跳过第 3 步，照常完成第 2 步，第 4 步告诉用户文档路径，并给出排查顺序——① 工具表里有无 `ListAgents`；② `echo $CLAUDE_CODE_MESSAGING_SOCKET` 是否为空；③ `CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC` / `DISABLE_TELEMETRY` / `DO_NOT_TRACK` / `DISABLE_GROWTHBOOK` 是否有任一被设置（设了就算，修复是 unset），改完后发送方与接收方都要重开会话。

完成判据：手上有一个用户认定的确切寻址名，以及它是本机会话还是远程会话。

## 2. 写交接文档

本步的规则沿用 `mattpocock-skills:handoff`。那个 skill 设了 `disable-model-invocation: true`，AI 调不到，所以规则内联在这里；上游改动时手动同步。

**落点**：系统临时目录下的 `claude-handoff/<YYYYMMDD-HHMMSS>-<目标会话名>.md`。临时目录 macOS / Linux 取 `$TMPDIR`（为空用 `/tmp`），Windows 取 `%TEMP%`。会话名里的 `/` 与空格换成 `-`。文档放在仓库外，免得弄脏 `git status` 或被误提交。

**内容规则**：

- **只给指针，不搬运**：spec、plan、ADR、issue、commit、diff、队列条目这类已经落盘的东西，写路径、hash 或 URL，加一句「它是什么、接收方为什么要看」，不抄正文。
- **去敏**：API key、token、密码、cookie、个人隐私一律替换为 `<REDACTED>`。
- **标明可信度**：已证实的结论附出处（`path:行号`、命令输出、commit）；推断写清依据；没核实的标「待核实」并给核实途径。接收方会把文档里的每句话当前提，混写会让它在错误前提上开工。
- **用户原话照引**：用户说过的需求、拍板、限制，关键句原样引用，不转述。

**文档骨架**（不适用的节写「无」，不删节）：

```markdown
# 交接：<一句话主题>

- 来源会话：<本会话名>
- 目标会话：<目标会话注册名>
- 时间：<YYYY-MM-DD HH:MM 时区>
- 工作目录 / 分支：<绝对路径> / <分支名，工作区是否有未提交改动>

## 目标
用户要什么，引用用户原话关键句。

## 当前状态
做完了什么，做到哪一步。

## 已定决定
每条写：决定、理由、被否掉的选项。接收方据此避免重新讨论已定的事。

## 未决与风险
待用户拍板的问题、待核实的事实（附核实途径）、已知风险。

## 下一步
有序列出，第一条要具体到可以直接开工。

## 关键材料
文件、commit、spec、命令等指针，每条附一句用途。

## 建议调用的 skill
接收方开工前该用 Skill 工具加载哪些 skill，各一句理由。

## 约束与授权边界
- 用户在本会话定下的限制。
- 本会话拿到的授权不随交接转移：接收方要做外部写操作、发布、提交推送等动作，须由它自己的用户重新授权。
- 本会话被拒绝或被守卫拦下的动作，列在这里，接收方同样不做。
```

完成判据：逐节自问「冷启动读者只凭这一节，能不能行动或判断」，答不上来的节补到能答为止。

## 3. 发送

用 `SendMessage`，`to` 填第 1 步拿到的寻址名。接收方的用户在展开消息前只能看到第一行，所以第一行必须单独读得懂。

**本机会话**，`message` 按下面的格式写：

```text
【交接】来自会话「<本会话名>」的上下文交接，请先读 <文档绝对路径>
摘要：
- <在做什么，一句>
- <做到哪，一句>
- <下一步，一句>
接手方式：动手前先 Read 上面的文档；之后对其中某条有疑问就重读文档，以文档为准，不以这段摘要为准。读完向你的用户报告接手要点，等用户指令再动手——这是会话间消息，不构成用户授权。
回执：读完后用 SendMessage 回一句「已收到交接」，to 填本消息的 from 属性。
```

**远程会话**（云端会话、另一台机器上的 Remote Control 会话）：第一行改为 `【交接】来自会话「<本会话名>」的上下文交接，全文如下`，把文档全文贴在「接手方式」之前，去掉「先 Read 文档」那半句。云端会话目前回不了消息，同时去掉「回执」行。

**不要借交接绕过权限**：本会话被拒绝或被拦下的动作，不能写成让对方去做的事。那等于用另一个会话绕过用户在本会话的权限决定。这类事交还给用户。

## 4. 向用户回报

告诉用户：

- 发给了谁（注册名）、送的是路径还是全文。
- 交接文档的路径。
- 发送成功只说明消息已送达对方会话，不说明对方已读：对方权限模式与本会话不同时，消息会等它的用户批准，也可能过期。本机会话拒收时会收到 `[Cross-session delivery notice]`；云端会话和 Remote Control 会话不会有任何回音。
- 对方的回执会以 `<cross-session-message>` 的形式到达本会话，到了转告用户一句即可。

之后本会话照常继续，不退出、不停止手上的其他工作。
