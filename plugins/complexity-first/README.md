# complexity-first — 复杂度优先

按需决策 skill：动手新增之前先证明必要性、按固定顺序穷尽复用路径，只在全都不成立时写最小新增实现。

## 一句话用法

> 要新增功能、文件、脚本或依赖之前，先让 Claude 走一遍复杂度优先流程，拿到一份「为什么写这些新代码」的决策记录。

## 这个 skill 干什么

六个步骤，命中即停：

1. **必要性** —— 需求能否不新增就达成（改配置、调参数、组合既有行为）
2. **现有代码、抽象与配置** —— 仓库内已有实现或半成品，优先扩展
3. **标准库** —— 语言自带能力，零依赖
4. **平台原生** —— 操作系统/运行框架/云平台内置能力
5. **已有依赖** —— 项目已装依赖的既有 API
6. **最小新增实现** —— 以上全不成立才写，且只写需求要求的面

每次建议输出一份五项决策记录：方案比较、选择、放弃理由、不可删边界、验证。

## 安装

- **Claude Code**：安装插件后 skill 自动可用，支持 `/complexity-first` 直调与语义触发。
- **Codex CLI**：在市场根目录运行 `node scripts/install-codex.js --plugins=complexity-first`，默认复制到当前项目的 `.agents/skills/`；加 `--scope=user` 才复制到 `~/.agents/skills/`。

## 触发边界

- **触发**：用户提出新增功能/文件/脚本/依赖，或说「先复用」「最小实现」「别造轮子」；也用于审查一段即将新增的代码是否真的必要。
- **不触发**：修 bug、改既有实现、纯重构且只修改既有代码时；已拍板方案的实施细节；用户已明确指定实现路径。修复或重构需要新增函数、文件、配置或依赖时，仍先走复用搜索。

## 边界

- 纯按需 skill：无 hook、无命令、无常驻注入——不开就完全不在场。
- 五类边界（安全、权限、错误处理、数据完整性、无障碍）在每次建议里保留，「最小」不砍边界。
- 需求存在规格空白时要求澄清，不替用户定义业务行为。
- 与 `token-saver` / `working-discipline` 不冲突：那些是常驻纪律，本插件是按需决策流程，可同装。

## 验证

跑一遍 skill 后自查四点（详见 SKILL.md 末尾）：六步顺序未跳、放弃理由每条写得清、五类边界逐条过、规格空白交还用户。
